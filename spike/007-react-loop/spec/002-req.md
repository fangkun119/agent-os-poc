| 术语 | 含义 |
|---|---|

| connector / starter | connector=连接器：对接某家大模型的实现代码。starter=Spring Boot 的开箱即用依赖包，引入一个坐标就带齐该连接器的全部依赖与默认配置 |

| 兼容端点 | MiniMax 提供的"说别家协议"的接口：OpenAI 兼容端点（`https://api.minimax.cn/v1`）与 Anthropic 兼容端点（`https://api.minimax.cn/anthropic`；2026-09-14 起统一用国内站），共用同一把 key |
| 四元组 | 每个 Provider 一组四个环境变量：`*_API_KEY` / `*_BASE_URL` / `*_DEFAULT_MODEL` / `*_MODEL_LIST`（定稿 §2.2） |

| 显式映射 / 类型扫描 | 显式映射=按"provider 名 → ChatModel 实例"建映射表取用；类型扫描=扫描 Spring 容器里所有同类型 Bean 来找实现。本项目禁类型扫描（TS 3.2） |

### 1.1 Q7：操作性表述与依赖事实错位（7 处清单）

2026-09-13 设计评审第一轮的问题 Q7 发现：docs（`docs/design/` 下四篇：DemandAnalysis / TechnicalSolution / AiProgrammingGuide / IndustryResearch）里有操作性表述写"基于 Spring AI Alibaba 做 LLM 调用"。但依赖事实不是这样。

范围口径（先读这段，防漏改也防扩面）：

- Q7 的 7 处修正清单只覆盖 TS 与 DA 两篇（见下表）。"7 处"是评审当场点名的数量，不是全量。
- 同类操作性表述（同样写"SAA 承担 LLM 调用"）经逐篇复查还有 5 处：AiProgrammingGuide（AG，见 0.2 节）的 §3.4 技术栈选型行、§4.1 核心目标 / 环境搭建类 / 锁版本三处，加 TS 3.2、DA 1.1 各一处（见下方补充清单）。本轮联动修改一并纳入（5.2 / 5.3 节已列对应条目）。
- IndustryResearch 属背景文档、不做实施依据（根 CLAUDE.md「仓库地图」），其同类表述不在本轮修正范围。

依赖事实（出处：007 README 的 D2 决议 + `spike/007-react-loop/pom.xml`）：

1. 实际引入的模型连接是 Spring AI 官方双腿 starter（`spring-ai-starter-model-openai` / `spring-ai-starter-model-anthropic`），接 MiniMax 双协议兼容端点；

3. SAA 自家的 connector 一个都没用上。

一句话：文档说"用了 SAA 做模型调用"，实际"SAA 只管了对版本号，模型调用走的是 Spring AI 官方 starter"。表述与事实错位。
