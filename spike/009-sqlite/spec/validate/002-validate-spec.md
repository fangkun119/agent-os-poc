## 2. 清单项 2：判据可执行——通过

六条判据逐条核对均落在命令输出或可观察现象上。抽 3 条推演：

1. **spec 2.2 判据 1（PRAGMA 回读期望值）**：正向组按连接串设参后，从连接池取连接依次执行 `PRAGMA journal_mode` / `PRAGMA busy_timeout` / `PRAGMA synchronous`，比较回读值与期望（`wal` / `5000` / `2`）。三个期望值都是具体数字或枚举串，判定无模糊空间。负向对照的可执行性经本机 sqlite3 3.51.0 独立复现（2026-10-09）：全新文件无参回读 journal_mode=delete、synchronous=2；同文件设 WAL 后 synchronous 回读 1——与 spec"缺省值不预设、以实测为准"的注记相容。
2. **spec 2.5 判据 1-3（计时数字与判据线）**：`System.nanoTime` 包住每次单行提交，1000 次累计得总耗时，除以 1000 得单次均值，两组相除得 FULL/NORMAL 倍数——三个数字都是机械计算产物；判据线"单次 FULL 提交均值 < 10ms"是一个可回答 yes/no 的明确问题，两分支各有下文（维持原文加注记，或触发 req 第 7 章联动 3 改写）。
3. **spec 2.6 判据 1（依赖仲裁输出）**：`mvn dependency:tree` 在 `spike/009-sqlite/` 目录执行，grep 两构件坐标即可判定"各只出现一个版本、来源 BOM 仲裁"——命令、期望输出形态、判读方法三者齐备。

其余判据同样可执行：D1 的 `PRAGMA table_info` 两份快照逐列对照与行数对照值留档、D3 的行数=5 / 回滚后=0 / BUSY 异常类型名与消息原文、D4 的 AssertJ 断言与 DDL 快照检索——全部是命令或可观察现象，无"凭感觉判"的条目。
