# CLAUDE.md 草稿生成器（claude-md-draft-for-tech-constrain）

## 目标

把项目已有文档提炼为一份（或多份）CLAUDE.md **草稿**：回答"这个仓库是什么、什么不能做"的常驻导航与红线。产出是**供人裁决的草稿，不是生效规则**——skill 不写落点 CLAUDE.md，是否拷入、如何合并由用户执行。

**边界**：
- 只从已有权威文档提炼，不发明约定；文档没有的好约定 → 标"项目约定（文档未明文）"，经用户确认后才写入
- 不修改源文档；用户手写内容一律保护，绝不静默删改
- **不写落点 CLAUDE.md**：既有 CLAUDE.md 只读，作为对照输入；全部产物落 {OUTPUT_DIR} 工作区（见下节）
- 检测到 AGENTS.md 等同类载体 → 询问"单一权威源+指针"还是双写，不静默双写

## 输出路径与占位符（与 claude-md-draft-for-code-standard 设计同口径）

交付物（草稿）固定落：

```
./{OUTPUT_DIR}/consolidate/{YYYYMMDD}_claudemd_draft_{name}.md
```

- `{OUTPUT_DIR}`：用户指定，未指定默认 `chat`；空值按默认并告知；相对 cwd；目录不存在则创建。**{OUTPUT_DIR} 整体子树是本 skill 唯一写盘根**
- `{YYYYMMDD}`：运行日本地日期 8 位，**必须取自时钟命令（`date +%Y%m%d`），禁止模型凭记忆写**
- `{name}`：第 1 步盘点后生成；公式 = `主框架-语言或形态-仓库角色` 三段式（示例 `vitepress-vue-docs` / `springboot-java-monolith`）；字符集为小写英文字母 + 数字 + `-`；连字符不连用、不出现在首尾；≤32 字符，超限先截"仓库角色"段再按连字符边界截断
  - **撞名即区分**：检查对象是完整 token `{YYYYMMDD}_claudemd_draft_{name}`——同时查 `./{OUTPUT_DIR}/consolidate/` 下的交付文件与 `./{OUTPUT_DIR}/draft/` 下的工作区目录，任一已存在即撞名
  - 撞名 → 给 `{name}` 追加数字序号（`-2`、`-3`，取未占用的最小序号），重入撞名检查直至唯一
  - 序号不豁免 ≤32 字符上限：追加序号越限时按既有截断顺序压缩 `{name}`、预留序号位（两位序号至多 3 字符），压缩后重入撞名检查
  - 同日不同落点 → 追加第四段语义区分（`-docs`/`-site` 类）；区分后仍撞 → 走序号规则
  - 连撞 ≥5 次仍无可用名 → 问用户改名
- 过程产物（候选笔记）落 `./{OUTPUT_DIR}/draft/{YYYYMMDD}_claudemd_draft_{name}/`，默认保留，`--no-draft` 可关；目录受版本管理时提醒用户可自行 gitignore
- 同日多次运行完全独立、互不覆写：已交付文件永不被后续运行覆写，各次运行以唯一 token 落新路径（撞名即序号区分）

## 不变量（任何项目必须遵守）

1. **选材三标准**：每条候选过三道筛——高杠杆（AI 真的会犯、代价大）、稳定（项目换到任何阶段仍为真）、精炼（能一行不两行）
2. **分层定位**：CLAUDE.md 只答"什么不能做"；"现在做什么/进行到哪"（任务清单、US/依赖链、周计划、一次性动作）一律排除，**包括"当前任务信息去哪看"的指针**——活信息的源随项目阶段漂移，修法是删除声明而非换指向
3. **红线写法**：结论 + 后果 + 出处；原则段对权威来源声明从属关系（"冲突时以 X 为准"），仲裁句取代同步纪律；无宪章类文件时以最高层技术文档的关键决策章节为权威源并同样标注
4. **五条去重判据**：位置机制（目录级 memory 承载的只放目录）、工具机制（自带加载体系承载的流程规则让位，只留一行机制存在性指针）、权威文件（从属复述不抄流程）、受管理区块（不复制其指向的内容）、时效（无任何"当前/现在"指称）
5. **排除项表**：列"考虑过但排除的内容+理由"，一等公民输出
6. **必问清单**（固定 5 项，见下）；**手写内容保护**与 **generated 标记区**

## 默认值（可偏离，候选笔记写明理由）

体量 ≤110 行且 ≤3500 字符；目录级文件 ≤2 个；骨架菜单节取舍；来源标注格式。

## 执行流程

### 第 1 步：盘点输入与准入判定

1. 读取 `$ARGUMENTS`；为空则扫描仓库找候选源文档
2. 确认文档集的**角色映射**（需求权威/技术权威/流程权威/背景），不按文档形态要求——四件套、ADR 集合、单份 README、RFC 目录均可映射；角色缺位时在候选笔记注明并按缺位处理
3. 探测项目的工作流约定体系（`.specify/`、`.cursor/`、`.claude/commands/`、CONTRIBUTING 流程节、Makefile/slash 命令目标）——探测到则其流程规则让位（不变量 4）
4. 探查项目信息生成 `{name}`（按"输出路径与占位符"规则）；检查既有 CLAUDE.md（**只读**）：识别用户手写段落与既有条目，作为对照输入——草稿将含「与既有条款冲突/重叠对照」节
5. **准入判定**：无权威文档 → 停止并汇报，建议先补文档；文档间存在重大冲突 → 建议先做文档评审，用户确认"按 X 为准"后可继续；存在既有评审报告 → 作为可选输入采用其结论

### 第 2 步：建立文档地图

各文档章节清单、引用关系、每类信息的权威源、冲突仲裁规则（哪个领域以哪份为准）。

### 第 3 步：选材与起草候选笔记

按不变量筛选，起草候选笔记（写入 `./{OUTPUT_DIR}/draft/{YYYYMMDD}_claudemd_draft_{name}/`；用户显式指定过程目录时优先）。结构：

```
分节候选正文（每节附入选理由 + 逐条来源）→ 排除项表 → 体量评估 → 分层放置说明 → 需拍板项清单
```

**位置决策判据**（自问）："能否构造一个 agent 全程不在该目录工作、但仍会违反这条规则的场景？" 能 → 根级放自含式一行（非纯指针）；不能 → 仅目录级。最高危红线（标题锚点、宪章保护类）无论判定结果在根级保留自含一行双保险（≈25 tokens）。目录级候选（按"子包有独立构建边界+独立文档"筛）向用户确认，上限默认 2 个——草稿以根级为主体，确认后的目录级内容写入同文件「目录级分流建议」节；用户要求独立成稿时另出文件（`{name}` 追加 `-目录名` 段）。

### 第 4 步：三视角自查（按视角性质定执行方式，与文档量无关）

| 视角 | 检查法 | 执行方式 |
|------|--------|---------|
| 事实核查 | 逐条候选 → grep 源文档对应位置 → 取原文逐字比对；来源标注覆盖实际引用；无已修订旧表述 | 始终机械化，主 agent（grep 天然去偏差） |
| AI 执行杠杆 | 提取项目纠偏/常见挑战清单 → 逐项在候选中找承接；条目写法强度 | 至少与本表下一视角之一走 fresh-context subagent |
| 取舍合理性 | 逐条排除项反问"指针够用吗"；入选有无违反稳定标准；与权威文件重叠策略 | 同上——起草者不得同时扮演这两个视角 |

降级：仅当全部视角可机械化且文档极小时允许主 agent 顺序自查，汇报标注"单上下文自查，未经独立复核"。

自查产生的拍板项合并为第二轮 AskUserQuestion（全程最多两轮）。

### 第 5 步：生成草稿

- 落盘路径：`./{OUTPUT_DIR}/consolidate/{YYYYMMDD}_claudemd_draft_{name}.md`
- **文件头草稿声明**（首行 blockquote）：本文件为草稿、非生效规则；生成日期与来源文档集；是否拷入落点 CLAUDE.md 由用户裁决
- 生成内容包在标记区块：`<!-- generated START -->` … `<!-- generated END -->`（标示机器生成范围，供使用方合并时参考）
- 既有 CLAUDE.md 的手写内容不进入本文件（只读对照）；需吸收的经用户确认后改写为草稿条款
- 既有 CLAUDE.md 存在时，草稿含「与既有条款冲突/重叠对照」节：逐条三值判定（兼容/冲突/未覆盖）
- 末尾加演进规则一行（给人看的说明，不作程序分支依据）
- 目录级分流建议见第 3 步判据

**输出骨架（菜单式）**：

必选节——

```
> 草稿声明（日期/来源文档集/非生效规则/拷入由用户裁决）
# {项目} — 一句话定位 + 范围红线（不含时限数字）
## 仓库地图 — 文档/目录导航、仲裁规则（自含式一行）、快查指针（不带计数值）
## 非协商原则 — 权威来源忠实压缩 + 从属仲裁句 + 补充红线（后果+出处）
（条件节）与既有条款冲突/重叠对照 — 既有 CLAUDE.md 存在时必含
（末行）演进规则
```

菜单节（按取用条件）——架构关键事实（存在"不知道就会写错方向"的结构性事实时；每行一条+行末来源，指向可定位的稳定位置：章节化文档"编号+标题"、ADR 编号、无结构文档"文件名+小节名"）；实施工作流（项目无自带工作流机制时展开；有任何约定体系时只留一行存在性指针）；构建与验证（构建非行业默认或有安全红线时）；阅读注记（存在易误读表述时）。

形态规则：条目一律单行列表 + 行末来源，不用多列表格；高频红线前置、操作型内容收尾；超限第一响应是目录级分流，截断是最后手段且汇报中明示。

### 第 6 步：汇报

屏幕输出（**第一项必须是产出文件路径**，让使用者能直接找到文件）：

1. **产出草稿的完整路径**：`./{OUTPUT_DIR}/consolidate/{YYYYMMDD}_claudemd_draft_{name}.md`（相对 cwd 或绝对路径）
2. 结构概览、实测体量（wc -l 行数 / wc -m 字符数，**不报 token 数**）
3. 排除项表摘要、根/目录分工表、自查质量等级（是否经独立复核）、候选笔记路径
4. 提醒：草稿非生效规则，拷入落点 CLAUDE.md 是用户动作；修复源文档是独立工作

## 必问清单（固定，不自行增减）

1. 无文档出处的新约定是否写入
2. 根/目录归属按判据仍拿不准的条目
3. 既有 CLAUDE.md 存在时，冲突/重叠条目的处置（逐条：吸收改写/保留既有/并列呈现）
4. 连撞 ≥5 次仍无可用名时——请用户改名（撞名自动序号区分，问人是最后手段）
5. 同类载体（AGENTS.md 等）单一权威源还是双写

其余（选材、压缩、措辞）自行决定，汇报中说明理由。

## 产出语义（2026-09-03 更新）

每次运行全新生成 draft：不读取、不比对、不增量补写既有草稿。交付路径唯一：落盘前按撞名规则检查完整 token，撞名即给 `{name}` 追加序号区分，**永不覆写既有文件，也不问覆盖**。同日多次运行完全独立、互不覆写；已交付文件永不被后续运行改动。新 draft 与既有文件（旧 draft、落点 CLAUDE.md）的替代/合并取舍由使用方裁决执行，不在本 skill 职责内。`<!-- generated START/END -->` 标记区仅标示机器生成范围，供使用方合并时参考。

## 反模式（不要做）

| # | 反模式 | 原因 |
|---|--------|------|
| 1 | 枚举本体（端点/命令/配置清单）抄进来 | 必过期；只放"清单见 X"指针 |
| 2 | 时限性内容（周计划、阶段时长、一次性动作） | 过期后是每次会话的持续噪音 |
| 3 | 当前任务/US 状态与依赖链（"A→B→C"） | 隐性时限内容，完成即过期 |
| 3b | "当前/现在/活信息在哪"类权威声明（即使是指针） | 活信息的源随阶段漂移，删除而非换指向 |
| 4 | 无出处约定不问用户直接写入 | 会被 AI 当权威代代相传 |
| 5 | 纯指针替代自含式关键规则 | 触发场景不在目标目录时等于没有 |
| 6 | 覆盖/删除/移动既有 CLAUDE.md 的受管理区块与手写段落 | 破坏工具产物；静默摧毁用户内容 |
| 7 | 实现细节步骤进 CLAUDE.md | 属 spec 层，读权威文档即可 |
| 8 | 与权威文件逐条"同步维护"的承诺 | 用从属仲裁句替代 |
| 9 | 用 @path 导入目录级 CLAUDE.md 到根文件 | 无条件加载破坏按需注入的惰性分流 |
| 10 | 指针带计数值；事实条目用多列表格 | 计数必过期；表格易碎，单行列表+行末来源消费效率最高 |
| 11 | 复述工作流工具自带的流程约束 | 调用时自动注入，复述=双份维护+漂移 |
| 12 | 把草稿直接写进落点 CLAUDE.md（即使用户口头催促） | 拷入是用户裁决动作；用户要求合并时明确提示由其执行或显式二次确认 |

## 运行原则

- **只读源文档与既有 CLAUDE.md**：全程不改被提炼文档，**永不写落点 CLAUDE.md**；产物只写 {OUTPUT_DIR} 下的草稿与候选笔记
- **证据优先**：每条候选附来源；每条排除附理由
- **可机械执行的优先**：事实核查、计数、来源跳转用 grep/wc 实测，不凭印象
- **不确定必问**：必问清单之外发现的无出处约束、归属争议，停下来问
- **全新生成**：每次运行全新产出 draft，替代/合并取舍由使用方决定（见「产出语义」）
