## 1. 证据分级 S1-S5

来源编号与名称：SRC-1 已有代码目录 / SRC-2 会话记录与事故复盘 / SRC-3 库依赖清单 / SRC-4 技术栈口述 / SRC-5 项目约束文档（正文简称「指南」）/ SRC-6 现成编程规范文档。来源编号与证据分级 S1-S5 是两套编号，互不相干。

分级按证据来源映射，不绑定输入形态。分级的唯一作用是封顶四维中的「必要性」维（见 §3.1）。

| 等级 | 名称 | 证据来源 | 判据与约束 | 必要性封顶 |
|---|---|---|---|---|
| S1 | 事故级 | SRC-1 代码实测，或 SRC-2 会话记录与事故复盘（`incident-log`）中记录的事故 | build 挂或运行时静默失效；须附可复核实况：file:line 或复盘原文引用 | 可给 5 |
| S2 | 盘点级 | SRC-1 代码盘点，或 SRC-2 会话复盘中的缺陷盘点结论 | 实测违反但未酿事故 | 上限 4 |
| S3 | 指南级 | SRC-5 指南明文（`guide-evidence`） | 指南记录的坑不得冒充实测 | 3 |
| S4 | 判例级 | 落盘业界规范（`industry-reference`）。`crawled` = 第②步调研爬取落盘；`user-provided` = SRC-6 本地判例⓪拷入 | `user-provided` 验证状态标 `local_provided`、免 URL 验证：不判死链，也不标 `fetch_failed`。`crawled` 来源无法核验时标 `fetch_failed`（未能核验），禁止标死链 | 3 |
| S5 | 推断级 | 模型知识无出处，含仅由 SRC-3 依赖清单或 SRC-4 口述直接推出的条款 | 默认不单独支撑正文——进待沉淀节或否决清单；**纯推断组合例外**（无 SRC-1/2/5/6 的运行）：可入正文，但必须逐条标「检验基准降级」，且强制待沉淀节兜底 | 默认不支撑正文；纯推断组合下降级标注后可支撑 |

### 1.1 配套枚举

- 验证状态四态（登记于 `research-index.md`，随候选 ID 全程传递）：`url_verified` / `cross_checked` / `local_provided` / `fetch_failed`。
- `local_provided` = SRC-6 本地判例⓪拷入，本地在手免 URL 验证；验证失败 ≠ 链接失效，禁止一票否决判死链。
- 判例来源 provenance 三值：`crawled` / `user-provided` / `pre-packaged`。`crawled` 属支路一（不含 SRC-6，判例经第②步调研爬取落盘）；`user-provided` 属支路二（SRC-6 独占，⓪ 拷入本地判例后 ③-⑨ 全量照走）；`pre-packaged` = 元规范路读随包 `references/meta-norms.md` 的条目（非调研、非用户输入，验证状态固定 `local_provided`）。
- 证据来源标签随来源走：`code-evidence`（SRC-1 实测踩坑，最硬）/ `guide-evidence`（SRC-5）/ `industry-reference`（判例）/ `incident-log`（SRC-2）。
- S1 / S2 的来源仅限 SRC-1 与 SRC-2。指南记录的坑不得冒充实测，不得按 S1 / S2 计级。

### 1.2 内容保真与行号腐烂纪律

- 引用判例时，每条实质陈述（数字、类名、配置键、机制）必须能在落盘原文找到出处；禁止凭记忆引用。
- 正文条款不携带行号。旧行号会诱导把已修复项当缺陷复改——这是腐烂红线。
- file:line 只存在于工作产物，且必须标注快照基线：盘点基线日期 + commit 短哈希，或文档快照日期。
- 已修复项必须标注「已修复」，防止复改。
- **转写强度对齐**：正文条款的模态强度与限定范围不得超过源证据的承载。源证据为建议性措辞（should / 推荐 / 宜 / 原文自认优先级低）时，条款不得写成绝对禁令（一律 / 禁 / 不得）；源证据限定于特定场景（如仅预处理器、仅某版本实测）时，条款必须携带同一限定；单版本观察不得外推为跨版本断言。理由：保真不只保内容、也保强度——条款强于证据时，执行者按字面执行会误伤合法场景，而只核「引用是否真实」的内容保真检查发现不了这类失真。⑧的配套核验见 review.md §3.2「强度-证据对齐核验」。

## 2. 准入一票筛（先于评分）

- 先筛后评：未过准入的候选不进入四维评分。
- 只收有客观违反判据的条款。判据三选一：
  - 有仓库（SRC-1）→ 以代码对照 git diff 为判据；
  - 无仓库有 SRC-5 指南 → 以指南原文或官方实测行为为判据；
  - 判例级证据（含 SRC-6 本地判例）→ 以落盘判例原文为判据：与判例原文中可检验的要求相抵触即算违反。
- 直接出局四类，命中任一即出局：不可判 / 裁量性 / 触发面为空 / 可从代码推导。出局条目记否决清单，落 `draft/final-selection.md`（该文件由③创建）。
- **选材判据分工（防重复检查与职责漂移）**：准入一票筛只问「可判吗」（客观性）；证据分级 S1-S5 只问「坑是真的吗」（真实性）；四维评分中的 AI 犯错要件只问「AI 会犯吗」（相关性）；重 / 扩管「值多少」，合管「写得清」。各判据只回答各自的问题，不互相替代、不重复检查。

## 3. 评分公式与档位线

### 3.1 四维权重公式（第③步执行）

- 综合分 = 必×0.3 + 重×0.3 + 合×0.2 + 扩×0.2；四舍五入到 0.5（round 0.5）。每维 1-5 分。**四维语义唯一权威定义如下，执行者不得另行操作化**（历史缺口：「重 / 合 / 扩」曾未定义，迫使运行时即兴仲裁）：
  - **必（必要性）**：这条值得写进 AI 指令文件吗——两个要件同时评。
    - 证据要件：按 §1 证据分级 S1-S5 封顶（S1 事故 5 / S2 盘点 4 / S3 指南 3 / S4 判例 3；S5 见 §1 S5 行）。
    - **AI 犯错要件**：条款针对的错误是否 AI（编码 agent）真实易犯。打分前必须写出「AI 为什么会犯」的一句话机制（例：长上下文遗忘、幻觉不存在的配置键 / API、禁令字面执行过宽、常见写法惯性套用），机制依据三选一——本仓实证 / 复盘、判例或官方文档标注的常见错误、AI 行为通识。写不出机制且无实证 → 必 ≤2；错误属人类失误模式、AI 在检查器 / 构建反馈下不会犯（纯审美偏好类）→ 必 ≤2。理由：CLAUDE.md 的读者是 agent——AI 不会犯的坑写进去只占行数、稀释遵从率。AI 犯错要件是打分判断、不是条款证据：不得据此抬高证据分级或绕过准入筛；「AI 行为通识」只支撑打分，机制依据仅通识、无其他来源的条款证据等级仍按 S5 处理。
  - **重（严重度）**：违反后果等级——事故（build 挂 / 运行时静默失效）4-5；缺陷（行为错误但可发现）3；风格 / 可维护性 1-2。
  - **合（可执行性）**：能否构造客观违反判据且字面执行无歧义——一行可 diff 的违反判据 = 4-5；需裁量 = 2-3；纯主观 = 1。
  - **扩（触发面）**：适用广度——通用（任何同类项目适用）4-5；同类栈 2-3；站点特定 1-2（必须落参数清单键）。
- 反惰性约束，三条必须同时满足：
  - 每维打分必须引用证据，或明确指出证据缺失（必维的 AI 犯错要件引用「机制依据」）；
  - 组内横向校准：同组候选对比打分；
  - 禁止全部给中间分。
- 记录载体：`candidates.md` 评分表。字段 = 候选 ID / 四维 / 综合 / 档位 / 来源标签 / 迁移性三值。候选 ID（`C-{nn}`）生成后全程稳定；正文条款经 ID 回查证据链。

### 3.2 讨论稿档位线（第③步打初档）

- ≥4 → 固化；2.5-4 → 一行；<2.5 → 不添加。
- 使用阶段：仅第③步初档。初档「固化」条目是第④步对抗验证的输入（拟固化条目）。
- 终取舍以终选线为准（见 §3.3 与 §4）；第⑦步起草一律以第⑥步终档为准。

### 3.3 终选档位线（第⑥步审议）

- ≥4 → 入正文；2.5-4 → 逐条合议；一行提及档 → 审议能否并入相邻簇。
- 数字门槛按第 4 节的分组口径套用。

### 3.4 第③步配套评分参数

- 分组抽取：分组键 = 按判例文档分组，一份文档一组；SRC-6 大文档按章节拆组（同①大仓分批口径）。抽取 sub agent 数 = 组数。本地判例（支路二⓪拷入）与爬取判例（支路一②落盘）同池分组，provenance 随判例索引跟随；本地判例免 URL 验证，但不免通读。sub agent 并发分批执行，遵守 fan-out ≤8。
- 动笔前只读 SRC-5 骨架条目，防止重复立法；不读落点既有 CLAUDE.md（仅⑨事后对照）。
- 设 1 个裁决 agent，负责去重合并与实测核验。
- SRC-5 红线免评分：直入骨架，保留原文口径。
- 检验基准降级：仅推断支撑的条款（无判例、指南、盘点佐证）逐条标「检验基准降级」。纯推断组合（无 SRC-1、SRC-2、SRC-5、SRC-6 的运行，仅 SRC-3、SRC-4 类输入）下，该标注为强制效果。
- 原始候选 >250 条：先组内合并，再进入评分（候选 ≤250）。

### 3.5 豁免清单（骨架条目台账）

- 豁免清单 = 「免评分直入骨架」条目的台账；骨架不设独立产物文件，其台账即豁免清单。
- 收录判据：SRC-5 红线（唯一判据）；落点既有 CLAUDE.md 手写条款不作为产出参考，不入清单。
- 字段：条款原文 / 来源（文件与位置）/ 免评理由（唯一值：SRC-5 红线）。
- 宿主：`candidates.md`（与候选清单同文件防分叉）。
- ③抽取时登记；⑦起草时消费，写入草稿第 2 段固化骨架；无 SRC-5 红线条目的运行不设骨架段（第 2 段为条件段，存在 SRC-5 红线才有）。

## 4. 终选分组审议（第⑥步）

- 独立步骤（仲裁 skill-design.md 附录 B MF-1）：第③步只打初档（讨论稿线）；第⑥步分组终审议决，并落盘否决清单——第⑧步回潜 grep 的数据源由该清单提供。
- 按证据通道分三组审议，各组审议问题与门槛：
  1. 直接采纳组——审议条款价值：≥4 入正文；2.5-4 逐条合议。
  2. 官方出处组——审议「能否防止 AI 被官方文档字面误导」：项目实践与官方 best practice 字面冲突时，必须写成显式例外条款。
  3. 一行提及组——审议能否并入相邻簇：≥3 条同类可并。
- 合议与淘汰的倾向性：**「AI 犯错要件」不成立的条目（必 ≤2）优先淘汰或转待沉淀**，即便综合分触及 4.0——严重度与触发面再高，AI 不会犯的条款对 AI 指令文件价值有限。
- 合议淘汰必须记死因分类（四值枚举）：因果链自相矛盾 / 触发面为空 / 覆盖被占满 / 机制含混。淘汰条目进否决清单，落 `draft/final-selection.md`：死因枚举 + 特征 token 集，作为第⑧步回潜 grep 的数据源。
- 每条标迁移性三值：通用 / 同类栈 / 站点特定。标「站点特定」的条款必须落参数清单键。参数清单写法见 template.md。
- 抽查复核可再推翻评分结论；复核必须落复核记录。
- 终档后估算成稿行数，排牺牲顺序：口径 = 综合分升序，4.0 档不动。成稿行数受 ≤200 行红线约束（口径见 template.md）。

## 5. 推翻通道双保险

- 两处都可推翻评分结论，改判必须写明理由：
  1. 通道一（第④步对抗验证）：独立上下文怀疑论 agent，被明确授权推翻评分结论；逐条给 KEEP / KEEP✎ / DROP 判定。
  2. 通道二（第⑥步抽查复核）：见第 4 节；复核记录必须落盘。
- 零改判时仍必须保留「检查了什么」的记录。通道的价值用纠错计量。
- **改判消费闭合（第⑦步执行）**：起草时对④改判（KEEP✎ / DROP）与⑥抽查复核修正逐条核对落稿去向——每条修正必须恰有一个去向：落正文（按修正后措辞）/ 转待沉淀节 / 记驳回理由于 `final-selection.md`。禁止半截采纳（如正文写了「见待沉淀节」指针而待沉淀节无承接条目）。④对候选的滞后注记（如某结论被后续实证推翻）同样属于修正：⑦起草与⑨修订时按最新结论消费，禁止消费已被推翻的旧口径。
- **抽查复核最小覆盖（第⑥步执行）**：抽查不少于终档条款的 10% 且至少 1 条核到证据本体——回查判例落盘原文 / 盘点证据原文逐句比对条款措辞与限定，而非仅核候选 ID 存在与口径一致。只核「ID 真实存在」不构成完成核验。

### 5.1 第④步四类检查

通道一除推翻授权与 KEEP / KEEP✎ / DROP 判定外，对拟固化条目逐条执行以下四类检查；过程与结论落 `adversarial.md`：

1. 机制因果方向（含写反）。
2. 行号时效：对照当前代码复核，修复后旧行号必须勘误。无 SRC-1 代码输入的运行降级为对照判例、指南、盘点原文核对，并在 `adversarial.md` 写明降级。
3. 枚举完整性：官方枚举漏项会诱导 AI 反推「在用配置非法」。
4. 前提实测复验：无代码输入时，同样降级为判例、指南原文核对。

## 6. 双写规则与官方出处条款写法

- 双写规则：官方 best practice 与项目现实冲突的判例必须双写，只写其一都是缺陷。两处都要写：
  1. 正文写显式例外条款——防止批量「修正」；
  2. 勿再加清单记否决理由——防止重复论证。
- 官方出处条款写法：双段结构——「机制依据 + 与官方字面表述的例外裁决」。
- 溯源规则：正文不带出处。状态块必须记录「条款 ID ↔ 评分表 rank」映射，供回查。
