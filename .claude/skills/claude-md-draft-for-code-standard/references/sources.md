# sources.md — 判例来源与调研规则

> 本文件职责：规定判例来源与调研的全部规则——来源登记与落点拍板、判例来源二分与两支路执行、SRC-6 本地判例拷入细则、第②步全量调研（路线推导、关键词推导、总量封顶、抓取纪律）、四类判例跨栈起手名单、firecrawl 门控与调研降级语义、判例登记与引用纪律、产出语义、用户交互问 / 默认矩阵。
> 上游：skill-design.md（下称「上游设计文档」）的 §2（来源识别与二分）、§4（第⓪步落点拍板）、§3.2 与 §7（firecrawl 门控与问 / 默认矩阵）。下游：skill 打包时作为 references/ 底稿；运行期 agent 在 ⓪-⑨ 各步按对应节执行，其中③-⑨ 需回查登记与引用纪律。

## 0. 术语与落点锚定

- **来源编号**：SRC-1 已有代码目录 / SRC-2 会话记录与事故复盘 / SRC-3 库依赖清单 / SRC-4 技术栈口述 / SRC-5 项目约束文档 / SRC-6 现成编程规范文档。完整识别清单与用户话语示例由 SKILL.md 正文承载。
  - SRC-5 项目约束文档：SPEC / dev plan / AI 编程指南 / AGENTS.md 等圈定技术栈或记录方言约束的文档。技术栈证据 + 约束红线进骨架、不走落盘。
  - SRC-6 现成编程规范文档：属本地判例。⓪ 拷入登记；③-⑨ 全量抽取其中适合 CLAUDE.md 的条款子集；文档名 / 篇目即技术栈证据。SRC-6 与 SRC-1..5 互斥，混入即提示不支持并退出。
- **provenance（判例来源）三值**：`crawled`（第②步爬取落盘，仅支路一）/ `user-provided`（SRC-6 本地判例 ⓪ 拷入）/ `pre-packaged`（元规范路读随包 `references/meta-norms.md` 的条目，验证状态固定 `local_provided`）。
- **验证状态四态**：`url_verified` / `cross_checked` / `local_provided` / `fetch_failed`。`local_provided` = SRC-6 本地在手、免 URL 验证。
- **落盘位置**：判例原文落 `code-style-guidance/`；判例索引落 `draft/research-index.md`。工作区 = `{OUTPUT_DIR}/draft/{YYYYMMDD}_claudemd_draft_{name}/`。
- **保留策略**：运行结束后 `code-style-guidance/` 全部保留、无自动清理，业内规范原文供用户翻阅参考。
- **落点既有 CLAUDE.md 非输入源**：不在 SRC-1..6 任何来源之内，全源扫描不发现；用户显式提供时，说明其按设计仅用于⑨事后对照、不作为生产原料（D11，2026-09-03）。
- **落点拍板细则**（第⓪步执行口径，见上游设计文档 §4）：
  - 主 agent 确定性判断，不派 sub agent。
  - 按「独立技术栈或独立构建边界」判定落点。**一个落点 = 一次运行 = 一份规则文件**。
  - monorepo：列全部候选落点交用户选。默认逐落点运行；模块共性强的可加根级跨模块公约草稿（用户选择）。
  - 判不了边界问用户、禁猜。
  - 同时生成 `{name}`（探查源随输入来源取材）。
  - 产出来源登记表：逐源记录能力 + 分叉支路 + 调研范围初判，作为后续各步裁剪依据。
  - **默认全源扫描**：用户未显式指定来源组合时，登记前对 SRC-1…SRC-5 逐源自动扫描——在落点范围内、按各源识别条件找一遍，受盘点排除项约束。扫描属登记级轻量探查，不等于①盘点；深挖归对应步骤。
  - **含 SRC-6 时不扫描、不登记 SRC-1..5**（排他）。
  - 扫描结果逐源列明于登记表；全空走「以上全无」。
- **打包核对项**（见上游设计文档 §2 / §7 自足性硬要求）：skill 打包时核对 SKILL.md 正文已含上游设计文档 §2.1 六源识别清单表、§2.2 判例来源二分规则与用户话语识别示例。运行 skill 的 agent 无上游设计文档上下文，只读 SKILL.md 就必须能独立完成来源识别与分叉判定。

## 1. 判例来源二分（流程主分叉）

唯一分叉判据：输入是否含现成编程规范文档（SRC-6）。

- **支路一（不含 SRC-6）**：①盘点（输入含盘点能力来源时）→ ②全量调研落盘 → ③-⑨ 照常。
- **支路二（SRC-6 独占）**：
  - 跳过①（规范文档不是代码、无需盘点）与②（文档已在手上、无需任何爬取）。
  - ⓪ 将 SRC-6 拷入 `code-style-guidance/`，登记为**本地判例**：带 `> Source: 用户提供的本地路径 + 日期` 标注头，provenance=`user-provided`、验证状态=`local_provided`，文件保留原文件名（细则见 §3）。
  - **③-⑨ 全量照走**：条款抽取、评分、对抗验证、终选、起草、评审、落盘。目标是从规模庞大的原文中找出真正适合 CLAUDE.md 的条款子集，而非把原文当结果；SRC-6 大文档由③按章节分批抽取。
  - AI 指令元规范路照常保留（§5-D）。
- **不补差**：支路二不做任何调研爬取——用户只给「阿里巴巴 Java 规范」，就只从中提取 Java 规范写 draft；要覆盖其它技术栈，用户再跑一次 skill。
- **混合输入不支持**：SRC-6 与 SRC-1..5 任一同时出现 → 提示不支持并退出（建议按栈拆多次运行）。

## 2. 第②步执行规则（条件步：仅支路一）

- 第②步仅支路一（无 SRC-6）执行，动作为**全量调研落盘**。
- 支路二（SRC-6 独占）不执行本步：SRC-6 已在⓪拷入登记为本地判例（§3）；SRC-6 大文档由③按章节分批抽取。
- AI 指令元规范路不属于②的调研爬取：恒定保留，读本地 `references/meta-norms.md`（§5-D）。
- 产物：`code-style-guidance/`（判例原文）+ `draft/research-index.md`（判例索引）。

## 3. SRC-6 本地判例拷入细则

1. **判型先行**：用判别问句判型——「它是写给所有同类项目的通用代码规范（→SRC-6 本地判例拷入），还是圈定本仓库技术栈 / 记录本仓库约束的文档（→SRC-5 进骨架）？」现成规范文档不得误当 SRC-5 约束文档直入骨架；来源登记阶段先判型、再走支路。
2. **排他检查**：判型确认 SRC-6 后先查排他——SRC-6 与 SRC-1..5 任一并存 → **提示不支持并退出**（建议按栈拆多次运行）；含 SRC-6 时不做 SRC-1..5 全源扫描。落点既有 CLAUDE.md 非输入源（仅⑨事后对照）——自动扫描不发现、显式提供亦不登记为生产原料，排他不涉及它。
3. **拷入**：SRC-6 文档拷贝到 `code-style-guidance/`，登记为本地判例（支路二唯一判例来源）。
4. **标注头**：每份拷入文件带 `> Source: 用户提供的本地路径 + 拷入日期` 标注头。
5. **保留原文件名**：拷入文件不重命名。
6. **登记**：`research-index.md` 中 provenance=`user-provided`（区别于 `crawled`）、验证状态=`local_provided`。登记时机 = ⓪ 拷入时同步登记索引（支路二无②）。
7. **验证豁免**：`local_provided` 本地文档免 URL 验证；不判死链、不标「未知」。证据等级属判例级，分级细则见 scoring.md。
8. **时序独立性**：拷入不属爬取、不依赖门控；先行完成，不因门控失败回滚。
9. **同池消费**：本地判例与爬取判例同池分组抽取；provenance 随判例索引跟随候选 ID 传递；本地判例免 URL 验证，但**不免通读**。
10. **计量口径**：支路二无调研爬取——总量 20-30 封顶（§4.3）不适用；不计入「调研爬取判例 <3 份或全部 fetch_failed（未能核验）」降级判据（§7）。
11. **大文档分批**：SRC-6 文档通常规模庞大（数百页量级）。③抽取按章节分批 sub agents（同①大仓分批口径），从中筛出真正适合 CLAUDE.md 的条款子集。

## 4. 调研路线推导（支路一②专用）

### 4.1 路线推导公式（恒定）

- **每核心组件一路官方规范**，单路 ≤8 份。
- **恒定「输出物形态」路，按栈替换**：文档站 → 文案排版；API → 错误码版本化；CLI → 帮助文本惯例。
- **AI 指令元规范路**：读本地 `references/meta-norms.md`（预打包进 Skill，创建时一次性爬取）。此路不受二分分叉影响、恒定保留——「怎么写 CLAUDE.md」的元规范与「代码怎么写」的判例正交，现成代码规范文档替代不了。例外：用户显式提供 AI 指令类文档时，该类文档按来源登记规则处理。
- **monorepo**：按子栈拆路；元规范路全仓共享，不按子栈重复。

### 4.2 关键词推导（禁盲拉）

- 关键词来源：①盘点产物 / SRC-5 约束文档 / SRC-3 依赖清单 / SRC-4 描述。支路一不含 SRC-6，关键词来源不含 SRC-6。
- 无代码库的组合（纯推断输入）：直接按技术栈名推导关键词与路线；①⑤跳过不影响②执行。

### 4.3 总量封顶与裁剪

- 总量 20-30 份封顶（仅支路一有调研爬取，本节不适用支路二）。
- 超出上限按优先级裁剪：**官方一手 > 二手 > 社区**。被裁项记入未下载清单，不静默丢弃。

### 4.4 抓取与并发纪律

- 同一官方文档跨路只抓一次（跨路共享同一份落盘原文）。
- 调研路每批 ≤4 路；单次 fan-out ≤8。
- 上游限流 429 → 并发分批降级；分批后单批仍在上述上限内。

## 5. 四类判例起手名单（跨栈）

口径：**四类判例任何栈都存在，变的是名单**。名单按 §4.1 路线公式，对第⓪步登记的技术栈组件清单逐项推导。下表给出每类的归类判据与起手入口；「点名实例」仅为上游设计文档及其材料源中出现过的样例（出处见上游设计文档），用于示意格式与量级，不构成固定配额、不预设任何栈的必选项。

| 类 | 判例类别 | 归类判据 | 起手入口 | 点名实例 |
|---|---|---|---|---|
| A | 官方规范 | 各核心组件的官方一手规范 / 文档 | 第⓪步技术栈组件清单逐组件对应其官方文档。组件清单来自：①盘点 / SRC-3 依赖清单 / SRC-4 口述 / SRC-6 文档名篇目 | VitePress 与 Vue 官方文档（文档站栈）；Maven / Spring Boot 官方文档（Java 单体栈）；Go 官方文档（CLI 栈） |
| B | 风格指南 | 写给所有同类项目的通用代码风格规范，与 SRC-5 项目约束文档互斥（判型问句见 §3 第 1 条） | 该语言 / 领域业界公认风格指南。用户已下载的即 SRC-6 本地判例（⓪拷入登记，③-⑨ 全量抽取）；未下载的进支路一调研范围 | 阿里巴巴 Java 开发手册、Google Java Style；CSS Guidelines、Google 开发文档风格指南 |
| C | 区域化文案规范 | 按草稿语言匹配的区域化文案 / 排版规范（草稿语言跟随用户 prompt 语言）。「输出物形态路」中文档站形态必含此项 | 由草稿语言选定对应区域文案规范。多个候选时取单一主源、其余降参考，防止两份规范自相矛盾 | 中文文案排版指北（sparanoid/chinese-copywriting-guidelines） |
| D | AI 指令元规范 | 「怎么写 CLAUDE.md」的元规范（Claude Code memory + AGENTS.md 规范），与「代码怎么写」的判例正交 | **固定读本地 `references/meta-norms.md`**；运行时不推导名单、不爬取 | 预打包于 `references/meta-norms.md`（创建 Skill 时一次性爬取） |

D 类补充规则：

- 运行时 Read 本地 `references/meta-norms.md`：**不触发 firecrawl、不受门控、不受二分分叉影响**。
- SRC-6 现成代码规范文档**不能顶替** D 类路（两者正交），除非用户显式提供 AI 指令类文档。
- 元规范更新频率为季度级；预打包带来零网络依赖、零失败面；版本随 Skill 升级同步更新。

## 6. firecrawl 门控（本 skill 唯一工具绑定，用户显式决策）

1. **作用域**：仅支路一②的全量调研爬取。SRC-6 本地判例拷入（⓪）不属爬取、不在其内；AI 指令元规范路读本地 `references/meta-norms.md`、不在其内；**支路二无任何爬取动作，门控恒不触发**。
2. **前置检查时机**：支路一进入②的爬取子阶段前，前置检查 firecrawl 可用性（CLI 存在 + 凭据配置）。支路二不前置检查、不停机。
3. **可用**：爬取一律用 firecrawl，不以其他爬取方式顶替。
4. **不可用**：停止爬取并提示用户（附安装 / 配置指引）；不静默降级。已完成前序产物（盘点、本地判例拷入）保留；汇报列明缺口。
5. **支路二**：无爬取需求，门控恒不触发、不停机。
6. **问 / 默认**：用户显式声明零爬取 / 离线环境且属支路一 → 必须问——确认「跳过②调研并把缺口记入待沉淀节 / 未决参数」还是停机等待。完整问 / 默认矩阵见 §10。

## 7. 调研降级语义

1. **验证失败 ≠ 链接失效**：crawled 判例验证不通过 → 登记为四态中的 `fetch_failed`，语义 = 本次未能核验（可能是执行环境拦截，而非 URL 失效）。禁止一票否决、禁止判死链；宁可登记为未核验态，不可错杀判例。
2. **降级判据（原文口径）**：调研爬取判例 <3 份，或全部 fetch_failed（未能核验）→ 自动降级为纯 SRC-4 口述路，并在汇报中声明。登记值一律使用四态枚举（未能核验记 `fetch_failed`）；「unknown / 未知」为上游设计文档对未能核验的历史表述（演变背景见上游设计文档），同一情形不得据此判死链。
3. **SRC-6 本地判例不计入该降级判据**（支路二无调研爬取；免 URL 验证）。
4. 判例库整体未达可核验态时，降级只影响后续条款的证据等级与检验基准，不终止流程。被降级运行按纯 SRC-4 口述路的特殊效果处理：①⑤跳过、仅推断支撑条款标「检验基准降级」、强制「待沉淀节」。

## 8. 判例登记与引用纪律

1. `research-index.md` 登记字段：编号 / 标题 / 来源（provenance=`crawled` → URL；`user-provided` → 用户提供的本地路径；`pre-packaged` → 随包 `references/meta-norms.md`）/ 抓取或拷入日期 / 验证状态 / 所属路。
2. 候选 ID（`C-{nn}`）生成后全程稳定。provenance 与验证状态随判例索引跟随候选 ID 传递；正文条款经 ID 回查证据链。
3. **引用纪律**（不受门控与分叉影响）：抽取必通读落盘原文（本地判例 = 通读拷入原件；元规范 = Read 本地 `references/meta-norms.md`）；评审必回查原文；**禁止凭记忆引用**。
4. **语言约定**：判例原文保留原语言落盘；草稿语言跟随用户 prompt 语言；官方术语首现给原文括注。

## 9. 产出语义（每次运行全新生成）

1. **每次运行全新生成**：不读取、不比对、不增量补写既有草稿。候选、评分、评审、终稿全部重新生产，不继承既有运行的结论（评分 / 改判 / 否决）。增量 / 续跑 / 覆盖机制已于 2026-08-31 简化废除，演变背景见上游设计文档 §3.5 与附录 B MF-2 仲裁记录注记。
2. **替代 / 增量取舍不在 skill 职责内**：新 draft 与既有文件（旧 draft、落点 CLAUDE.md）的关系由使用方裁决与执行。skill 不提供 --update / 续跑 / 覆盖机制，不自动归档旧稿。
3. 既有 `code-style-guidance/` 判例原文可作为素材复用以免重爬，但不构成增量语义（不继承既有候选 / 评分 / 裁决结论）。
4. **每次运行路径唯一**：产物 token「{YYYYMMDD}_claudemd_draft_{name}」撞名即加序号区分——查 consolidate/ 下交付文件与 draft/ 下工作区目录两处，任一已存在即给 {name} 追加数字序号（`-2`、`-3`，取未占用的最小序号），重查直至唯一。同日多次运行完全独立、互不覆写，已交付文件永不被后续运行覆写。撞名因落点语义而起 → 追加第四段区分（`-docs` / `-site`），口径见上游设计文档 §3.3。序号不豁免 32 字符上限：追加序号会越限时，先按既有截断顺序（先截「仓库角色」段、再按连字符边界截断）压缩 {name}、预留序号位（连字符 + 序号数字，两位序号至多 3 字符），保证追加后总长仍 ≤32；压缩后的名字重入本条撞名重查，序号连撞 ≥5 次仍无可用名 → 问用户改名。

## 10. 用户交互问 / 默认矩阵（上游：skill-design.md §7 用户交互点矩阵）
