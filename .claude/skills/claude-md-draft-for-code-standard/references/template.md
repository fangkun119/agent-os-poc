# 草稿模板与红线（template.md）

> 职责：定义 CLAUDE.md 草稿的产出契约——五段骨架与行数预算、起草红线九条、状态块字段（整体置于第 5 段块级 HTML 注释区、不计行数）、参数清单与待沉淀节字段级模板，以及步骤①盘点执行规则与步骤⑤ Action 工单模板（含各栈验收四段实例）。
> 上游：skill-design.md 的 §4（步骤①⑤⑦）为主，兼收 §1、§2.3、§3.4、§5–§7 与附录 B、附录 C、附录 F 的相关约束。下游：步骤⑦ 起草与步骤⑨ 就地修订按本文件执行；skill 打包时本文件作为 references/ 底稿。

## 0. 术语与记号

- 来源编号沿用 skill-design.md §2：SRC-1 已有代码目录 / SRC-2 会话记录与事故复盘 / SRC-3 库依赖清单 / SRC-4 技术栈口述 / SRC-5 项目约束文档 / SRC-6 现成编程规范文档。
- 步骤号 ⓪ 与 ①-⑨：⓪ 为落点与分叉判定，①-⑨ 为调研与起草主流程。步骤引用写作「步骤⓪」「步骤①」；「③初档」「⑥终档」为对应产物文件的固定简称。
- 引用记法：「第 n 节」指本文件小节；「红线 n」指本文件第 3 节第 n 条；「skill-design.md §x」指主文档小节。

## 1. 版式总则

- 草稿版式 = 五段单文件；不设独立第二层状态文件。状态块全部字段整体置于第 5 段块级 HTML 注释区、不计行数；效力锚一行 blockquote 留正文、计入行数。（单文件版式出自 skill-design.md 附录 B MF-4；状态块承载位置见第 2.2 / 第 4 节）
- 草稿语言跟随用户 prompt 语言；官方术语首现给原文括注。（skill-design.md §7）
- 草稿是供人裁决的草稿，不是生效规则：skill 不写落点文件、不改被治理源码；是否拷入落点 CLAUDE.md 由用户裁决。（skill-design.md §1）
- 起草一律以⑥终选终档（`final-selection.md`）为准，不以③讨论稿初档为准。（skill-design.md 附录 B MF-1）
- 档位线两套。（skill-design.md §4③⑥）
  - 讨论稿线（③初档）：≥4 固化 / 2.5–4 一行提及 / <2.5 不添加。
  - 终选线（⑥终档）：≥4 入正文；2.5–4 逐条合议；一行提及条目评估能否并入相邻簇，≥3 条成簇。合议淘汰的条款记死因分类，四值为：因果链自相矛盾 / 触发面为空 / 覆盖被占满 / 机制含混。
  - 本文件的「入选正文」只收⑥终档 ≥4 条款。

## 2. 五段骨架与行数预算（skill-design.md §4 步骤⑦）

### 2.1 起草输入与产出

- 输入：⑥终档（`final-selection.md`）+ 固化骨架（仅 SRC-5 红线）+ 豁免清单（`candidates.md`）+ Action 工单（`actions.md`）。
- 产出：终稿写入交付路径（./{OUTPUT_DIR}/consolidate/{YYYYMMDD}_claudemd_draft_{name}.md）；步骤⑨ 就地修订，不另立文件。

### 2.2 五段结构（各归其位，不得合并、不得换序）

| 段 | 内容 | 契约 |
|---|---|---|
| 1 文件头 | 适用范围 / 技术栈 / 冲突裁决效力锚。效力锚 = 一行 blockquote 留在正文、计入行数；状态块不置本段，字段见第 4 节 | 效力锚写明：本文件为草稿、非生效规则；与落点既有 CLAUDE.md 冲突时以既有文件为准。skill 永不改写既有根级/目录级 CLAUDE.md；终稿是否拷入由用户裁决 |
| 2 固化骨架 | 条件段：存在 SRC-5 红线才设；无 SRC-5 输入的运行不设本段 | SRC-5 项目约束文档（SPEC/dev plan/AI 编程指南）的约束红线免评分直入骨架、保留原文口径；SRC-5 文档沿用「用户手写内容一律保护」。指南记录的坑不得冒充实测。免评分直入骨架条目的台账 = 豁免清单（candidates.md），免评理由唯一值 = 「SRC-5 红线」 |
| 3 入选正文 | ⑥终档 ≥4 的条款（终选线） | 条款带候选 ID（`C-{nn}`）可回查证据链。正文条款不带出处与行号，溯源走状态块「条款 ID ↔ 评分表 rank」映射；评分表落 `candidates.md` |
| 4 提示区 | 自描述演进纪律（红线 8 全文写入） | —— |
| 5 块级 HTML 豁免注记 | 人类专用元信息：勿再加清单 / 参数清单 / 复用方法 / 元规范出处 / 状态块（全部字段整体置本段注释区、不计行数）/ 遗留规范对照（⑨事后对照子块） | 只进块级 HTML 注释（红线 9）。注明这是 Claude Code 加载器实现行为而非格式通性，跨工具消费需另议 |

既有 CLAUDE.md 对照（非起草期正文条件节）：草稿正文不设「与既有条款冲突/重叠对照」节。落点既有 CLAUDE.md 非输入源，⑦及之前任何步骤禁止读取；⑨终稿落盘后做一次事后对照，三值口径 = 一致（仅计数）/ 差别（新增 = 新有旧无、未采纳 = 旧有新无）/ 冲突（同类话题结论相反），结果写入第 5 段注释区「遗留规范对照」子块与状态块「与既有 CLAUDE.md 的关系」字段。对照为只读，skill 永不写落点 CLAUDE.md。（skill-design.md §7 共存策略，D11 改⑨事后对照）

### 2.3 行数预算

- 红线：≤200 行。口径 = 注入后对 agent 可见行数 = 全文行数 − 以 `<!--` 开头的行数（唯一机械口径：`wc -l` 减 `grep -c '^<!--'`，禁止各步自创口径；⑨终局机检第 5 项以此实测回填，见 review.md §6）；状态块注释行不计入 200 行口径。（skill-design.md 附录 B MF-4）
- 落盘时记录三数：红线 200 / 估算 / 实况，写入状态块。
- 超行按牺牲顺序裁剪：综合分升序，4.0 档不动（红线 1）。

### 2.4 起草契约（步骤⑦强制项）

- 通用化 = 条件式 + 站点参数清单。禁两种歪路：
  1. 删光站点内容写正确的废话；
  2. 硬编码站点取值。
- 否定式需求扩写为显式边界条款：列出需要/不需要清单 + 优先级判据，不得只写一句禁令。
- 纯推断组合——无 SRC-1/SRC-2/SRC-5/SRC-6 的运行，如仅 SRC-4、仅 SRC-3、SRC-3+SRC-4——强制追加「待沉淀节」（模板见第 6 节）。配套效果：步骤①⑤跳过；步骤③对仅推断支撑条款逐条标「检验基准降级」。（skill-design.md §2.3）
- 候选全灭不产出空壳文件：无条款可写时终止并出终止报告，不落盘空模板。
- 未定稿参数占位、命令安全、挂起决策等正文写法约束，按第 3 节红线执行。

## 3. 起草红线九条（skill-design.md §6，逐条不可违反）

1. **行数上限**：全文 ≤200 行，口径 = 注入后对 agent 可见行数。五段结构各归其位。超行按牺牲顺序裁剪：综合分升序，4.0 档不动。
2. **无腐烂信息**：正文无行号、无日期、无项目品牌名/站名/内部路径；技术栈名是必要标识，须按官方拼写。配套要求（skill-design.md §5）：正文条款不携带行号——旧行号诱导把已修复项当缺陷复改；`file:line` 只存在于工作产物并标注快照基线；已修复项标注「已修复」防复改。
3. **条件式 + 站点参数清单**：参数清单为编号键值对表（字段见第 5 节），清单处标注「本清单为唯一权威」。已定填值、未定留空——质量梯度写在空格数上。
4. **未定稿参数占位**：一律 `TODO(参数名): 用途`。禁止把现状值当既定规范；禁止把不确定写成含糊「建议」。
5. **指令文件命令红线**：写入草稿的命令必须可安全重复执行。禁 `make clean` 与任何 rm/覆盖类破坏性命令。
6. **挂起决策不擅自落地**：呈现选项，不默默选边。未决期间，同主题不得写出矛盾条款。
7. **全文无不可判表述**；能从代码推导的不写。
8. **自描述演进纪律写进提示区**：可对照 diff 检验才增条；同类错误重复出现才增条；优先并入既有条目；≤200 行；无矛盾表述。
9. **人类专用元信息只进块级 HTML 注释**，覆盖六类：勿再加清单 / 参数清单 / 复用方法 / 元规范出处 / 状态块 / 遗留规范对照（⑨事后对照子块）。注明这是 Claude Code 加载器实现行为而非格式通性，跨工具消费需另议。

| `research-index.md` | 判例索引，字段为：编号 / 标题 / 来源 / 抓取或拷入日期 / 验证状态 / 所属路。来源登记 provenance 三值：`crawled` 登记抓取 URL；`user-provided` 登记用户提供的本地路径；`pre-packaged` 登记随包 `references/meta-norms.md` | 步骤② / ⓪ |

统一枚举（状态块、参数清单、待沉淀节引用时按此拼写）：

- 验证状态四态：`url_verified` / `cross_checked` / `local_provided` / `fetch_failed`。`local_provided` = SRC-6 本地判例经步骤⓪拷入，本地在手、免 URL 验证。验证失败 ≠ 链接失效；禁止一票否决判死链。
- 判例来源 provenance 三值：`crawled`（②爬取落盘）/ `user-provided`（SRC-6 本地判例⓪拷入）/ `pre-packaged`（元规范路读随包 `references/meta-norms.md` 的条目，验证状态固定 `local_provided`）。登记于 `research-index.md`，随候选 ID 全程传递。
- 证据来源标签：`code-evidence` / `guide-evidence` / `industry-reference` / `incident-log`。
- 候选 ID `C-{nn}`：生成后全程稳定；正文条款经 ID 回查证据链。

### 4.3 盘点执行规则（skill-design.md §4 步骤①单元格）

- 代码盘点产出「AI 会踩的坑」摘要，不是代码清单。记录盘点产出「复盘沉淀的坑」与「记录中提到的组件清单」，用原话引用 + 文档行号，禁脑补。
- 禁印象句（如「不够规范」）：盘点证据必须可复核。代码证据 = file:line + 计数 + 构建产物实况；记录证据 = 文档路径 + 行号。统一标注盘点基线：日期 + commit 短哈希，或文档快照日期。
- 规范候选与缺陷两线永不混写：约定候选线与缺陷清单线在 `inventory.md` 内分线记录，互不串写。
- 大仓按目录分批盘点，长记录按时间分段盘点。

### 4.4 Action 工单模板与判据（skill-design.md §4 步骤⑤单元格 + 附录 C.1）

- 触发条件：步骤①的缺陷清单非空，即代码盘点或记录盘点发现乱象。清单为空则不产出 `actions.md`，并在汇报中写明。
- 开单两句判据：第一句描述当前存在的乱象；第二句说明一次清理后无复发面。记录盘点来源的乱象同样适用：事故复盘沉淀的已知问题同样开单移交。
- 边界：永续纪律即使带缺陷子句也留正文条款，缺陷单独开单。
- skill 只识别、开单、移交用户：不改被治理代码、不跑清理构建；是否修复、如何修复由用户裁决。（skill-design.md §1 非目标）
- 每单六字段：

| 字段 | 填写要求 |
|---|---|
| 现象 | 乱象客观描述，回指 `inventory.md` 缺陷清单条目 |
| 判据 | 两句判据：现状乱象 + 一次清理后无复发面 |
| 建议修法 | 建议的清理方式，供参考、不代执行 |
| 验收四段 | 通式 = 可构建 / 产物或测试可核 / 运行时可探活 / 资源可回收，取自方法文章的验收链条段。按栈实例见下表 |
| 范围红线 | 逐项列「不要顺手修」的诱惑，供用户或后续会话执行修复时直接套用 |
| 尝试次数上限 | 同一问题的尝试次数上限 |

- 运行结束汇报必须列出全部工单摘要：现象 / 判据 / 建议修法 / 验收四段。供用户裁决是否修复。（skill-design.md 附录 C.1）

各栈验收四段实例（skill-design.md §4 裁剪总表末句）：

| 栈 | 验收四段实例 |
|---|---|
| Web | build 通过 / 核对 dist / preview 返回 200 / 杀掉进程 |
| Spring Boot | mvn verify / 服务探活 / 停进程 |
| CLI | go build / 实跑样例输入核对输出与退出码 / 无常驻进程 |
| monorepo | 只构建受影响包；monorepo 按子栈拆路，拆路规则以步骤②调研产出为准 |
| 纯文档仓 | 降级为链接与渲染抽查，且必须写明降级 |

## 5. 参数清单字段级模板（skill-design.md 附录 F 额外补充 + §6 红线 3）

- 承载位置：块级 HTML 注释（红线 9），并标注「本清单为唯一权威」。
- 表结构，每参数一行：

| # | 参数名 | 当前值 | 状态 | 影响条款 | 建议默认值 + 依据 |
|---|---|---|---|---|---|
| P-01 | （参数名） | （已定填值/未定留空） | `SET` 或 `PENDING` | C-03、C-07 | （建议值；依据：判例 ID / 盘点项 / 指南原文 / 官方出处） |

- 字段规则：
  - 状态两值：`SET` = 已定，填当前值；`PENDING` = 未定，当前值留空。质量梯度写在空格数上。
  - 影响条款编号双向索引：参数行列出受影响的条款编号；条款正文以条件式反向引用参数编号。
  - 建议默认值 + 依据：依据列必填，写明证据出处——判例 ID / 盘点项 / 指南原文 / 官方出处。
- 配套规则：
  - `PENDING` 参数在正文一律以 `TODO(参数名): 用途` 占位（红线 4）。
  - 迁移性三值（通用 / 同类栈 / 站点特定）中判为「站点特定」的条款，必须落参数清单键。（skill-design.md §4⑥）

## 6. 待沉淀节字段级模板（skill-design.md 附录 F 额外补充）

- 位置：入选正文之后的条件节；纯推断组合强制存在（§2.4）。
- 承接对象：仅推断支撑的条款，即无判例、无指南、无盘点佐证的 S5 推断级条款，含仅由 SRC-3 库依赖清单、SRC-4 技术栈口述直接推出的条款。此类条款默认不得单独支撑正文，进待沉淀节或否决清单；纯推断组合例外——可入正文但逐条标「检验基准降级」，待沉淀节对本类条款强制兜底承接（例外口径见 scoring.md §1 S5 行）。（skill-design.md §5）
- 用户显式声明零爬取/离线环境、且属支路一、经确认跳过步骤②调研的：调研缺口记入待沉淀节或未决参数。（skill-design.md §7 问/默认矩阵）
- 每条沉淀项五字段：

| 字段 | 填写要求 |
|---|---|
| 观察触发器 | 何种观察发生时本条应被重新审视/升级，写成可检验条件 |
| 建议条款草案 | 条款草案文本；步骤③已标「检验基准降级」的随条保留该标注 |
| 当前替代做法 | 沉淀前项目当前怎么做 |
| 沉淀条件 | 满足什么判据才升入正文。与提示区增条纪律同口径（红线 8）：可对照 diff 检验、同类错误重复出现 |
| 关联判例编号 | 关联候选 ID / 判例索引编号；无判例写「无」并写明推断来源 |

- 待沉淀节条目属挂起决策：按红线 6 不得写成生效条款、不得默默选边；按红线 7 不得含不可判表述。
