# 编程规范 CLAUDE.md 草稿生成器（claude-md-draft-for-code-standard）

## 定位与边界

- **产出**：带完整论证链的 CLAUDE.md **草稿**——正文 ≤200 行 + 状态块 + 评分表 / 豁免 / 否决 / 判例索引归档，供人裁决后再落仓。**skill 不写落点 CLAUDE.md、不改被治理源码**：「把流程交给 Skill，把裁决留给人」。
- **与 claude-md-draft-for-tech-constrain 分工**：那边从项目已有文档提炼**设计层共识约束**（架构决策 / 模块边界怎么定，选好即用、无论证链归档）；本 skill 从技术栈与实战证据**提炼编程规范**（代码怎么写、坑怎么避，经论证链生产条款），治理 AI 编码行为。用户显式指定优先；两侧输入源可重叠（同一份 SPEC 可服务两侧），区分在目的与产出。
- **非目标**：不参与代码修复（Action 只识别、开工单，运行结束汇报列出全部工单供用户裁决是否修复）；不绑死任何单一技术栈；不固化和复用任何单次运行的产出物（条款原文、快照数字、案例叙事一律不带走）。
- **产出语义**：每次运行全新生成，无增量 / 续跑 / 覆盖机制；新 draft 与既有文件（旧 draft、落点 CLAUDE.md）的替代 / 合并取舍由使用方裁决执行。
- **语言约定**：草稿语言跟随用户 prompt 语言；判例原文保留原语言落盘；官方术语首现给原文括注。

## 输入来源识别（自足承载——运行 agent 只读本文件即可完成识别与登记）

来源是**开放集**：不预设三选一，运行时逐源识别、按「能产出什么」登记能力——提炼技术栈 / 盘点缺陷 / 判例落盘。来源叠加合法且常态。

| 序 | 识别条件 | 来源 | 能力 | 输入要求 | 证据等级 | 用户话语识别示例 |
|---|---|---|---|---|---|---|
| 0 | 用户显式指定来源组合 | 指定组合生效（不得混 SRC-6 与 SRC-1..5，混入即提示不支持退出） | 按该组合 | — | — | 「只用这份阿里规范立规，别调研」=SRC-6 独占 |
| 1 | 提供代码目录（或 cwd 即仓库） | SRC-1 已有代码目录 | 技术栈 + 缺陷 | 目录路径 + 可选排除项 | 实测踩坑（最硬，code-evidence） | 「扫描一下这个目录」 |
| 2 | 提供会话记录 / 事故复盘 | SRC-2 会话记录与事故复盘 | 技术栈 + 缺陷 | 文档路径 ≥1 | 记录级（incident-log；build 级事故=必要性上限） | 「结合这次事故复盘立规」 |
| 3 | 提供依赖清单（pom.xml / package.json / go.mod / Cargo.toml / requirements.txt 等） | SRC-3 库依赖清单 | 技术栈 | 文件 / 目录路径 ≥1 | 技术栈证据（非条款证据——仅由清单直接推出的条款按 S5 推断级，需判例佐证） | 「按这几个 pom 里的技术栈」 |
| 4 | 仅技术栈名称 / 描述 | SRC-4 技术栈口述 | 技术栈 | 自由文本（栈 + 产物形态 + 用途） | 业界常见坑 + 官方勘误，条目标「检验基准降级」 | 「给一个 Go CLI 项目立规」 |
| 5 | 提供项目约束 / 方言文档，或自动扫描发现（SPEC、dev plan、AGENTS.md、AI 编程指南等圈定技术栈或记录本仓库约束的文档） | SRC-5 项目约束文档 | 提炼技术栈 + 约束红线（进骨架，不走落盘） | 文档路径 ≥1（指定或扫描发现） | 指南记录的坑（guide-evidence，不得冒充实测） | 「按这份 spec 立规」/「结合这份风格指南」 |

| — | 以上全无 | 终止并询问 | — | — | — | — |

登记纪律：

- 序仅表示识别次序，**全部来源可叠加**（SRC-6 除外——排他）。
- 用户显式说出的限定语即视为显式指定来源组合（如「只根据这份指南」「直接从代码盘点」「这份阿里规范直接当判例，别再爬」）。
- SRC-5 与 SRC-6 的判别问句：「它是写给所有同类项目的通用代码规范（→SRC-6 本地判例拷入），还是圈定本仓库技术栈 / 记录本仓库约束的文档（→SRC-5 进骨架）？」
- SPEC / dev plan / AI 编程指南等**不因属于需求 / 方案类文档而排除**——圈定技术栈即入 SRC-5。
- **默认全源扫描**：用户未显式指定来源组合时，第⓪步对 SRC-1…SRC-5 逐源自动扫描并登记（落点范围内、按各源识别条件找一遍；登记级轻量探查 ≠ ①盘点，深挖归对应步骤）。SRC-6 不参与自动扫描（本地判例属用户显式行为）。
- **落点既有 CLAUDE.md 非输入源**：不属任何 SRC 形态、不参与自动扫描、用户显式提供亦不登记为生产原料——仅⑨终稿落盘后做事后对照。
- 判定失败（目录不存在 / 无源文件 / 依赖清单无法解析 / 文档缺失 / 描述不足）→ 逐项列实况询问用户，**禁止静默降级**（任何证据等级下降必须写明）。
- SRC-1 盘点默认排除项：`{OUTPUT_DIR}` 整体子树、`.git`、`node_modules` / `target` / `dist` / `build` / `vendor` / `__pycache__`、锁文件、生成代码与构建产物。例外：用户显式指定路径的输入文件（SRC-2 / SRC-3 / SRC-5 / SRC-6 文档）即使位于该子树内也照常读取——排除只针对自动扫描，显式指定即豁免。

## 判例来源二分（流程主分叉，自足承载）

唯一分叉判据：**输入是否含现成编程规范文档（SRC-6）**。

- **支路一（不含 SRC-6）**：执行完整流程——①盘点（含 SRC-1 / SRC-2 时）→ ②全量调研落盘 → ③-⑨。
- **支路二（SRC-6 独占）**：跳过①（规范文档不是代码、无需盘点）与②（文档已在手上、无需任何爬取）。动作：⓪ 将 SRC-6 拷入 `code-style-guidance/` 登记为**本地判例**——`> Source: 用户提供的本地路径 + 日期` 标注头，provenance=user-provided、验证状态 local_provided，文件保留原文件名。随后 **③-⑨ 全量照走**：条款抽取、评分、对抗验证、终选、起草、评审、落盘。SRC-6 文档通常规模庞大（数百页量级），不可能整体装进 CLAUDE.md——③-⑨ 的全部机制就是为了从中找出真正适合 CLAUDE.md 的条款子集写入 draft，而非把原文当结果；大文档按章节分批抽取（同①大仓分批口径）。
- **不补差**：支路二不做任何调研爬取——用户只给「阿里巴巴 Java 规范」，就只从中提取规范写 draft；要覆盖其它技术栈，用户再跑一次 skill。
- **混合输入不支持**：SRC-6 与 SRC-1..5 任一同时出现 → 提示不支持并退出（建议按栈拆多次运行）。
- **AI 指令元规范路恒定**：「怎么写 CLAUDE.md」的元规范路不受该分叉影响、恒定保留——它与「代码怎么写」的判例正交，无法从用户的现成代码规范文档获得（除非用户显式提供 SRC-5 / AI 指令类文档）。读取本地 `references/meta-norms.md`，属预打包本地读取、非调研。

## 输出与存储布局

```
./{OUTPUT_DIR}/
├── consolidate/
│   └── {YYYYMMDD}_claudemd_draft_{name}.md        ← 唯一交付物（终稿）
└── draft/{YYYYMMDD}_claudemd_draft_{name}/        ← 本次运行工作区
    ├── code-style-guidance/                        ← 判例原文（crawled=②爬取 / user-provided=⓪拷入，各带 > Source 标注头）
    └── draft/                                      ← 中间产物七件（职责表见 references/template.md §4.2）
```

占位符解析：

- `{OUTPUT_DIR}`：用户指定，未指定默认 `chat`；空值按默认并告知；相对 cwd；目录不存在则创建。**`{OUTPUT_DIR}` 整体子树是盘点 / 自动扫描的排除对象，也是本 skill 唯一写盘根**（显式指定的输入文件豁免，见上节）。
- `{YYYYMMDD}`：运行日本地日期 8 位，**必须取自时钟命令（`date +%Y%m%d`），禁止模型凭记忆写**。
- `{name}`：生成时机 = 第⓪步落点拍板后、①开跑前（全部产物文件名依赖它）。公式 = `主框架-语言或形态-仓库角色` 三段式（示例 `vitepress-vue-docs` / `springboot-java-monolith` / `go-cli-tool`）；字符集 = 小写英文字母 + 数字 + `-`，连字符不连用、不出现在首尾，≤32 字符（超限先截「仓库角色」段、再按连字符边界截断）。探查源随输入来源取材：有代码目录 → 目录名 + pom.xml / package.json 等 manifest；SRC-3 → 清单文件本身即一等探查对象；SRC-4 → 口述栈名；SRC-6 → 文档名 / 篇目中的栈名。
- **撞名**：检查对象 = 完整 token `{YYYYMMDD}_claudemd_draft_{name}`，查 `consolidate/` 下交付文件 + `draft/` 下工作区目录两处，任一已存在即撞名 → 给 `{name}` 追加数字序号（`-2`、`-3`，取未占用的最小序号）重查直至唯一；序号不豁免 32 字符上限（先按截断顺序压缩、预留序号位）；已交付文件永不被后续运行覆写。完整口径（含落点语义第四段、连撞 ≥5 次问用户）见 references/sources.md §9。

## 流程总览（速览；冲突时以下节步骤表为准）

```
⓪ 落点拍板 · 来源登记 · 分叉判定（恒定）
 ├─ 支路一（无 SRC-6）→ ① 盘点（条件：含 SRC-1/SRC-2）→ ② 全量调研落盘（firecrawl 门控只挂本步爬取）
 └─ 支路二（SRC-6 独占）→ ⓪ 拷入登记本地判例（跳①②；无任何爬取，门控恒不触发）
      ↓ 两支路在此汇合
③ 条款抽取与评分 → ④ 对抗验证 → ⑤ Action 识别（条件：①缺陷清单非空）→ ⑥ 终选分组审议
      → ⑦ 起草初稿 → ⑧ 三路对抗评审（fail-fast 最后一道闸）→ ⑨ 修订落盘 + 状态说明 + 汇报
```

## 步骤契约（⓪ + ①-⑨；细则按「references/ 使用指引」按需 Read）

| 步 | 条件 | 产物 | 契约要点 |
|----|------|------|----------|
| ⓪ | 恒定 | 落点元数据 + 来源登记表（写入本 run 全部产物头部：落点 / 来源组合 / 分叉支路 / 基线） | 主 agent 确定性判断，不派 sub agent。按「独立技术栈或独立构建边界」判定落点，**一个落点 = 一次运行 = 一份规则文件**；monorepo 列全部候选落点交用户选（默认逐落点运行，模块共性强的可加根级跨模块公约草稿，用户选择）；判不了边界问用户、禁猜。同时生成 `{name}`。登记表逐源记能力 + 分叉支路 + 调研范围初判，作为后续各步裁剪依据。输入含 SRC-6 时执行排他检查（混入 SRC-1..5 任一 → 提示不支持并退出）并先行拷入登记本地判例；无 SRC-6 且未显式指定来源时，登记前对 SRC-1…SRC-5 逐源自动扫描 |
| ① | 输入含盘点能力来源（SRC-1=代码盘点、SRC-2=记录盘点） | `inventory.md` | 独立 sub agent。代码盘点产出「AI 会踩的坑」、非代码摘要；记录盘点产出「复盘沉淀的坑 + 记录中提到的组件清单」——原话引用 + 文档行号，禁脑补。证据可复核：代码 = file:line + 计数 + 构建产物实况；记录 = 文档路径 + 行号；统一标注基线（盘点基线日期 + commit 短哈希，或文档快照日期）。禁印象句（「不够规范」类）。技术领域分类从盘点长出来（变量不预设）。规范候选与缺陷两线永不混写。大仓按目录分批、长记录按时间分段。执行规则 references/template.md §4.3 |
| ② | 仅支路一执行；**firecrawl 门控仅作用本步爬取** | `code-style-guidance/` + `research-index.md` | 路线推导公式恒定：每核心组件一路官方规范（单路 ≤8 份）+ 恒定「输出物形态」路按栈替换（文档站→文案排版、API→错误码版本化、CLI→帮助文本惯例）+ AI 指令元规范路读本地 `references/meta-norms.md`（预打包、非调研）+ monorepo 按子栈拆路共享元规范路。关键词从盘点 / 约束文档 / 依赖清单 / 描述推导，禁盲拉。总量 20-30 份封顶（超出按官方一手 > 二手 > 社区裁剪，记未下载清单）；同一官方文档跨路只抓一次；每批 ≤4 路、fan-out ≤8。门控（前置检查 firecrawl 可用性，不可用停止爬取并提示、不静默降级）、四类判例起手名单与调研降级见 references/sources.md §4-§7 |
| ③ | 恒定 | `candidates.md`（+ `final-selection.md` 准入出局段） | 分组抽取 sub agents（分组键 = 按判例文档分组，一份文档一组；本地判例与爬取判例同池，SRC-6 大文档按章节拆组）+ 1 裁决 agent 去重合并、实测核验。动笔前只读 SRC-5 骨架条目防重复立法，**不读落点既有 CLAUDE.md**。**准入一票筛**：只收有客观违反判据的条款——判据三选一：有仓库（SRC-1）→ 代码对照 git diff；无仓库有 SRC-5 指南 → 指南原文 / 官方实测行为；判例级证据（含 SRC-6 本地判例）→ 以落盘判例原文为判据。不可判 / 裁量性 / 触发面为空 / 可从代码推导的直接出局、记否决清单。四维评分（必 / 重 / 合 / 扩 = 0.3 / 0.3 / 0.2 / 0.2，加权后按 0.5 步长取整；四维语义唯一权威定义见 references/scoring.md §3.1），必要性按证据分级 S1-S5 封顶 + **AI 犯错要件**（写不出「AI 为什么会犯」机制 → 必 ≤2）；本步用讨论稿档位线（≥4 固化 / 2.5-4 一行 / <2.5 不添加）打初档。SRC-5 红线免评分、直入骨架、保留原文口径。仅推断支撑的条款逐条标「检验基准降级」。原始候选 >250 条先组内合并。评分细则 references/scoring.md |
| ④ | 恒定 | `adversarial.md` | 独立上下文怀疑论 agent，被明确授权推翻评分结论。四类检查：机制因果方向（含写反）；行号时效（对照当前代码复核，修复后旧行号必须勘误；无 SRC-1 代码输入的运行降级为对照判例 / 指南 / 盘点原文核对，并在 adversarial.md 写明降级）；枚举完整性（官方枚举漏项会诱导 AI 反推「在用配置非法」）；前提实测复验（无代码输入时同样降级）。每条 KEEP / KEEP✎ / DROP + 理由。**价值用纠错计量**——零改判也要留「检查了什么」的记录 |
| ⑤ | ①缺陷清单非空（代码盘点或记录盘点发现乱象） | `actions.md`（清单为空则不产出，汇报写明） | 两句判据：描述当前存在的乱象 + 一次清理后无复发面。记录盘点来源的乱象同样适用——事故复盘沉淀的已知问题开单移交。边界：永续纪律即使带缺陷子句也留正文条款，缺陷单独开单。**skill 只识别、开单、移交用户——不改被治理代码、不跑清理构建**。工单六字段：现象 / 判据 / 建议修法 / 验收四段 / 范围红线（逐项列「不要顺手修」）/ 尝试次数上限。运行结束汇报必须列出全部工单摘要。工单模板与各栈验收四段实例 references/template.md §4.4 |
| ⑥ | 恒定 | `final-selection.md` 终审淘汰段（终档 + **否决清单**，回潜 grep 数据源） | **独立步骤**（非③的延续）：③只打初档，⑥分组终审议决，起草⑦一律以⑥终档为准。按证据通道分组审议：直接采纳组看条款价值（≥4 入正文、2.5-4 逐条合议）；官方出处组看「能否防止 AI 被官方文档字面误导」——项目实践与官方 best practice 字面冲突必须写成显式例外条款；一行提及组看能否并入相邻簇（≥3 条同类可并）。合议淘汰记死因四值（因果链自相矛盾 / 触发面为空 / 覆盖被占满 / 机制含混）+ 特征 token 集。每条标迁移性三值（通用 / 同类栈 / 站点特定，站点特定必须落参数清单键）。抽查复核可再推翻（落复核记录）。终档后估算成稿行数、排牺牲顺序（综合分升序，4.0 档不动）。审议细则 references/scoring.md §4 |
| ⑦ | 恒定 | 终稿初版（⑨就地修订，不另立文件） | 以⑥终档为准。按预算结构五段：文件头（适用范围 / 技术栈 / 冲突裁决效力锚）→ 固化骨架（条件段：仅存在 SRC-5 红线时设，红线原文口径）→ 入选正文 → 提示区 → 块级 HTML 豁免注记（状态块全部字段整体置本段注释区、不计行数）。**≤200 行红线（口径 = 注入后对 agent 可见行数，即全文减 HTML 注释行）**，记录 200 / 估算 / 实况三数。通用化 = 条件式 + 站点参数清单，禁两种歪路：删光站点内容写正确的废话 / 硬编码站点取值。否定式需求扩写为显式边界条款（列需要 / 不需要清单 + 优先级判据）。纯推断组合追加「待沉淀节」。**④改判消费闭合**：KEEP✎ / DROP 与⑥复核修正逐条核对落稿去向（落正文 / 转待沉淀 / 记驳回），禁止半截采纳。候选全灭不产出空壳文件，终止报告。五段骨架、状态块字段与模板 references/template.md §2 / §4-§6 |

| ⑨ | 恒定 | 终稿 + 汇报 | must_fix 全部修复后落盘；就地修订。状态说明三要素（来源组合与证据等级 / 未决参数 / 待沉淀节指针）+ 变更记录写入状态块；`review.md` 末尾追加「修订完成」标记。**遗留规范对照**：落点既有 CLAUDE.md 仅本步终稿落盘后可读（⓪-⑧一律不读——独立性硬保证）；落点无既有文件时对照记「无既有文件」即可。对照三值：一致（仅计数）/ 差别（新增 = 新有旧无、未采纳 = 旧有新无）/ 冲突（同类话题结论相反），差别与冲突逐条列（条款定位 + 两侧各一句话摘要）；落终稿末尾块级 HTML 注释区「遗留规范对照」子块。**落盘前终局机检**（fail-fast：指针闭合 / 条款冲突扫描 / TODO 键名逐字相等 / PENDING 字段格式 / 行数三数唯一机械口径复核；命中一律 must_fix——修复或显式改判后重跑，全过才写「修订完成」标记）。遗留对照以逐话题两侧结论对照表判定，差别与冲突逐条全列、禁止「列 N 项代表」缩水；落点含既有 CLAUDE.md 且运行中读过落点目录文件的，执行**注入污染披露**：状态块记「对照受注入污染风险」，对照结论标注「仅供人工参考，不作为合并唯一依据」。汇报六项：终稿路径、三行数（200 / 估算 / 实况）、来源组合与证据等级、未决参数、Action 移交清单、遗留规范对照摘要。收尾契约 references/review.md §6 |

补充口径：

- 纯推断组合（无 SRC-1 / SRC-2 / SRC-5 / SRC-6 的运行，如仅 SRC-4、仅 SRC-3、SRC-3+SRC-4）特殊效果 = ①⑤跳过 + ③对仅推断支撑的条款逐条标「检验基准降级」+ ⑦强制「待沉淀节」。
- 支路一调研爬取判例 <3 份或全部 fetch_failed（未能核验）→ 自动降级为纯 SRC-4 口述路并声明；**SRC-6 本地判例不计入该降级判据**。
- **验证失败 ≠ 链接失效**：crawled 判例无法核验标 `fetch_failed`，禁止一票否决判死链。验证状态四态 = `url_verified` / `cross_checked` / `local_provided` / `fetch_failed`；判例来源 provenance 三值 = `crawled` / `user-provided` / `pre-packaged`（元规范路固定 `local_provided`）；证据来源标签 = `code-evidence` / `guide-evidence` / `industry-reference` / `incident-log`；候选 ID（`C-{nn}`）生成后全程稳定。

## 草稿红线九条（⑦起草与⑨修订逐条不可违反；全文与配套细则 references/template.md §3）

1. **行数上限**：全文 ≤200 行，口径 = 注入后对 agent 可见行数；超行按牺牲顺序裁剪（综合分升序，4.0 档不动）。
2. **无腐烂信息**：正文无行号、无日期、无项目品牌名 / 站名 / 内部路径；技术栈名是必要标识，须按官方拼写。
3. **条件式 + 站点参数清单**：参数清单为编号键值对表，清单处标注「本清单为唯一权威」；已定填值、未定留空。
4. **未定稿参数占位**：一律 `TODO(参数名): 用途`；禁把现状值当既定规范、禁把不确定写成含糊「建议」。
5. **指令文件命令红线**：写入草稿的命令必须可安全重复执行；禁 `make clean` 与任何 rm / 覆盖类破坏性命令。
6. **挂起决策不擅自落地**：呈现选项，不默默选边；未决期间同主题不得写出矛盾条款。
7. **全文无不可判表述**；能从代码推导的不写。
8. **自描述演进纪律写进提示区**：可对照 diff 检验才增条；同类错误重复出现才增条；优先并入既有条目；≤200 行；无矛盾表述。
9. **人类专用元信息只进块级 HTML 注释**，覆盖六类：勿再加清单 / 参数清单 / 复用方法 / 元规范出处 / 状态块 / 遗留规范对照。注明这是 Claude Code 加载器实现行为而非格式通性，跨工具消费需另议。

## 交互纪律与失败预防

- 问 / 默认总原则：可逆有默认 → 默认；不可逆无默认 → 问。完整矩阵 references/sources.md §10。
- **默认不问**：OUTPUT_DIR 默认 `chat`；多来源叠加（SRC-6 排他除外）；未显式指定来源 → 全源扫描登记；fetch_failed 降级；评审 must_fix 自动修订；SRC-6 独占运行——⓪ 拷入登记本地判例，不询问。
- **必须问**：技术栈无法推测且口述含糊；用户显式声明零爬取 / 离线环境且属支路一（确认跳过②调研还是停机等待）；OUTPUT_DIR 不可写 / 越界；用户要求改源码或覆盖非本 skill 产物——拒改、可转工单。
- **提示退出**（不问、直接终止）：混合输入——SRC-6 与 SRC-1..5 任一并存，提示不支持并建议按栈拆多次运行。
- 已知失败模式十条登记表 references/failure-modes.md：命中「症状」即执行对应「预防规则」，禁止静默忽略。
