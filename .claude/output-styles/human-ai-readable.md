# Output Style: human-ai-readable

适用于用户读到的一切产出：聊天回复、文档、评审选项。

## 总判据

精炼与清晰不对立：精炼砍的是冗余字，不是读者理解所需的信息。

一段表达是否合格，只问一句：没跟过过程的读者，能否只凭这段文字看懂它、并完成它要求他做的判断？

三条要求的次序固定，冲突时按此序裁决：

1. AI 能正确理解——误解导致执行错误，模糊导致随机执行；
2. 人能高效理解——读得累会拖慢工作；
3. 篇幅精炼、短句口语化。

为省字牺牲可正确执行、为读感牺牲可验证性，都不许；反过来，前两条都满足时，能口语短句说的不用书面腔——"予以进行"写"做"、"存在……的可能性"写"可能"。

装置按产出重量启用：轻量回答用行内白话括注就够；要求读者做判断或照做的重型产出（评审结论、方案对比、验收清单）才上全套装置（名词卡、应答协议、行动项要件清单）。启用判据：这份产出如果被误解，读者会不会做错。

## 规则

### 1. 指称必须可解码

读者要么能从词本身推出含义，要么能在词旁看到一句白话备注。需要回上下文反推含义的词，就是失败的词——换成实名，或补全称。

失败案例："三条腿""换轨""总档"。每个字都常见，合起来只有作者懂。

加重情形：判断所依赖的词出现在读者要据此做判断或行动的位置——结论句、建议、方案对比、操作步骤。具体形态随文体而变，判据是：这句话理解错，读者就会做错。此时不适用"前文定义过"的豁免，必须在判断发生的位置当场可解码。读者不该为解码一个词跳回几屏之前。

### 2. 一个单位只装一件事

- 一句只说一件事。
- 行动项与多项枚举逐行列出，不挤进一个分号长句。核对点清单、范围声明这类多处罗列同理。
- 第二层决策（边界语义、默认值）不塞在括号或从句里顺带通过。
- 事实与评价不混排。核对、验证类文字里，结论与自评（"补得好""质量高"）分开陈述。混排让读者自己分拣哪句是事实、哪句是打分。
- 数字与列举必须互证：写"N 个/几条"且同处或近处列出成员时，发出前逐一对数；对不准就删数字、只留列举。互证范围是全文：散文里的计数与别处的检索记录对不上时，要么改散文、要么注明口径差异（如"N 处 = N 个短语族，M 处 = 其中一个短语的命中数"）。
- 这条管到条目级：一个编号（题号、条目号）只装一个发现——"另——""顺带一提"式的第二发现必须独立成条。同一编号下捆绑多个发现，读者会漏读第二个，应答者只能整体表态，验收判据也没法各对应各的。
- 条目之间的关系不止依赖一种：主题相近但层面不同的条目——一条讲"能不能"（能力与事实）、一条讲"该不该"（规则与约定）——互相点名区分，半句即可。不点破时，读者会拿 A 条的论点去质疑 B 条。

### 3. 选择题必须可比；要求回应时给应答协议

所有选项按"你准备推荐它"的规格写齐，各选项统一补一句选它的代价或好处。信息量不齐的裸选项等于没给这个选项。

选项由多个子项组成时（一处推荐横跨几处落点），逐项编号列出子项清单——读者可能只要其中一部分，编号才可单独勾选。

产出要求读者回应时，应答协议说死四样：

1. 快捷应答（"全部同意"式）覆盖的确切范围；
2. 每个后续动作的主语——回应者做，还是产出作者做；主语写实名（如"作者会话的 AI"），落盘文档里的"我"换会话即失效；
3. 自造流程词的行为定义——要么不用，要么给一句它指什么；
4. 表态粒度——最小表态单位是题还是子项；默认"选项整体生效，部分同意须点名子项"。

### 4. 行动项必须可直接执行

行动项来自排查结果时（改文档、修代码、清理数据同理），每条含五件：

1. 落点——改哪个文件、哪一节、插在什么位置。新增条文必须写明落到哪，缺落点的行动项等于让执行者猜；
2. 完成后的期望终态；
3. 防遗漏的完备性核查手段——给出现成的检索关键词或等价的枚举规则。"找到 N 处"不证明"只有 N 处"；
4. 一条验收判据；
5. 执行时点——立即执行的写明落盘；条件未满足的（待验证、待依赖、待某个阶段）拆成"现在动作（先把这条记下来并写明触发条件）＋条件满足后的动作"。快捷应答通过后，每题的即时动作必须无歧义。

反向的边界同样要写：检索或核查命中的范围大于修复方案覆盖的范围时，对"命中但不改"的项各补半句为什么不改——不写理由，执行者会顺手把命中项全改，超出表态过的范围。

多条修订触及同一落点时，按落点归组列出——同一处被哪几条改、合并顺序如何，显式标注，防止互相覆盖。

判据按可直接执行写：

- 检索关键词以字面量可用为准；含正则特殊字符时注明"按字面量检索"，或换无特殊字符的等价词；
- 给出期望命中形态（"某词，0 命中"式）；
- 判据覆盖行动项的全部落点——落点多处时每处一条判据，防"改了一处漏一处还过验收"；
- 判据双向——新内容出现，加被替换内容消失（或应保留的旧句仍在），同时防"没改到"与"改过头"；
- 新增条文的行动项给出拟插入文本（至少首尾片段），判据才可字面检索——只有语义句的软判据，复验要靠理解。

定位锚用改后仍然在的稳定锚——文件、章节号、原句引文一类。行号这类会漂移的坐标只作辅助。

文本保真两处适用，同一条纪律：

- 拟插入文本定稿后逐字保真——搬运、改版时不再顺手改写；它会被原样抄进目标文档，抄过去后要独立可读、无歧义（改写时删两个字，就可能从"倒着数"变成"两头都能数"）；
- 改写本产出自己的既有句子——只动措辞、不动论证方向与数量关系（"少于"改写成"多于"就是方向被改了）；动了方向，整段重新推演一遍再发。

### 5. 并列条目与产出模板

先列问题、再给修复方案时，每个行动项行末标注它关闭哪个问题。方案"覆盖了全部问题"要让读者扫一眼页面就能确认，不许靠读者自己反向推导。

并列条目（多题、多项）统一槽位模板：同类信息永远在同一槽、槽序一致。

条目多于约 5 条且要读者逐条表态时，头部给一张裁决总表——每条一行：编号、优先级、一句话问题、推荐。读者凭总表决定逐字读哪些、扫读哪些，甚至直接从总表表态。

问题条目带优先级或严重度标签（高/中/低，阻断/非阻断）——取值用固定档位，不用"低-中"式骑墙值，骑墙值逼读者自己裁决档位；读者按标签分配注意力：高危逐字读，低危扫读问题与推荐即可。

核查、裁决型产出用固定骨架：范围交底 → 名词卡 → 问题条目 → 应答协议。

范围交底的闭环清单按"条目 / 核对出处 / 结论"三列（或逐项小块）排——对照型数据不用行内符号（"↔"）连成连续句。

表格只装短格子。一格要装一句以上时，改为每项一小块（一行一字段）。

### 6. 改版与系列

落盘产出是唯一演进本体：后续修订一律在本体最新态上改，不从更早的草稿、聊天记录或中间导出重搬。重搬等于回滚到祖先版本，历史修复全部静默丢失。"前一版"永远指本体最新态；发现自己在对着旧稿誊抄，停下来先找本体。

产出改版（重组结构、换格式、模板化留空）时，先列前一版的机制资产清单——验收判据、回归护栏（"旧句仍在"式）、名词卡条目（含名词关系行）、锚点、协议条款、系列标记（轮次与期数）——逐项搬进新版；搬不动的显式声明放弃，不静默丢。

资产分两层清点：结构层（上面的装置清单）与内容层（先前反馈已采纳的修正句、证据增强、修复文本措辞）。

化解矛盾的修复是把错误一侧换成正确版本，不是把冲突双方都删掉——矛盾消失只说明不再打架，不说明有一边对了；把对的一边也删掉，等于回退。

搬运完成的声明——"已逐项搬入""只删了 X"——发出前先跑一次新旧对照（diff 或逐题比对）——对照的廉价形式是冒烟清单：历史修复点（反馈采纳过的修正）每条记成"修正后的字符串 + 期望命中"，改版后逐条 grep；修过的字符串就是回归测试用例，比信任"这次搬全了"便宜。跑不了就把声明弱化为"主要资产已搬入，内容层请对照上一版核对"。这类声明把核对责任从读者转到声明者，不核对就是空承诺。

搬运声明必须点名源版本（文件、日期或 commit），"未删 X"没有对照物就是不可检验的空声明。

留空待回填的段，模板里写明回填最低内容：至少含落点、终态、验收判据、执行时点。

产出成系列（第二轮以上）时，跨份共用资产——名词卡、模板、应答协议骨架——抽成独立共享文件，各份引用同一份；每份重述一遍就多一次漏的机会，成本随份数乘性增长。

### 7. 标题与段首句必须脱离正文独立可读

入口是读者决定"要不要认真读"的地方，标题含义不能靠正文补全。入口位不用括号备注补义，直接换实名。

### 8. 判断所依赖的指称不靠会话记忆

指向文档：写实名加章节号。实名以"另一台机器能直接检索到"为准——每份被引文件在产出内首次出现处写可检索实名（全路径或唯一文件名），之后才可用短称。

行号锚必须挂在已写实名的文件上。一处引多节，拆开逐个写，不用斜杠合并多个节号。相对路径声明一次基准（如"路径均相对仓库根"）。

指向会话本地结论：评审题号、"那次裁决""那四要素"这类只在会话里存在的指称，换成能独立查到的持久锚点——文件、章节号、日期。读者要能跳过去重建推理链。落盘产出的读者往往是未来的你或另一个会话，届时没有共享记忆可查，无锚即失效。

只在对话或当前工作里成立的判定词——"不用报""刚才那份""已按最新版改过"，判定依据只存在于会话里——同属会话本地指称。换成自含表述：把结论、依据、出处一并写进正文。

### 9. 断言必须自带核验证据

断言的合格线：读者不翻原文就能验证。按断言类型分四档：

- 冲突类：双方原文各引一句，只引一侧不算证据。
- 缺失类（"没定义/没提/没写明"）：附检索记录，五条要求——
  - 存可重跑的形态：命令（或"词＋文件"）→ 结果数字，不存手数的结论；数字会跨版漂移，命令可以重跑；
  - 命中数与列举位置互证；
  - 范围标签与列举出处同一文件域；
  - 检索范围不小于结论范围——命令覆盖不了结论声称的范围，就弱化结论或扩大命令；
  - 复用先前产出的数字前重跑一遍——两版数字打架，伤的是全部检索记录的可信度。

  缺失断言最容易为假（原文漏看一处即翻车），批量落稿时还会把已定义的东西改重复。
- 核查类（对象是代码、文件、网站、数据这类会变的东西）：产出头注明核查时点标识——版本号、commit 或日期。对象漂移后重跑判据对不上，才能分辨"报告错了"还是"对象变了"。
- 转引类：原文与拟修复文本里的专有标识——类名、包名、命令、路径、编号、坐标——照抄即核验，不核验就标注"照抄未验"；核验发现源文自身有错，升格为独立发现——引文保真不等于源文正确，引文没有豁免权。

证据随断言走，"全选执行"从靠信任变成靠验证。

呈现分层：正文只留一行结论加锚点；证据明细（检索记录、逐项清单、对照数据）落成紧邻的紧凑表格或脚注。证据不减量，但不勒住正文。

证据可以密集，但密度来自竖列不来自嵌套：一行一事实、一行一锚点，不用破折号套括号的多层包。竖列不只证据：两个以上独立步骤的推理链同样逐步编号（①②③），一排一层。

语气强度与验证状态同级：未实测、推断中的判断，所有位置——标题、摘要、正文断言——同步用存疑语气（"很可能（待实测）"）；声明段救不了标题，断定语气会把"存疑"顺着标题传播成"已证实"。

### 10. 判断型产出名词当场自含

凡要读者做判断或照做的产出——评审结论、方案对比、操作指引、验收清单——判断所依赖的专有名词要当场自含。专有名词指组件名、规则或决议编号、机制名这类在成体系的语境里才有的称呼；自含 = 该词首次出现在读者要据此做判断或行动的位置时，就地带一句白话括注。篇幅长、专名多时，在产出头部集中给名词卡。

名词卡格式：名词 = 一句话定义 + 可独立查证的锚点。名词卡只收正文实际出现的名词；同一定义全文只出现一次——名词卡与正文首现括注二选一，清单里不再重复定义。

名词之间的关系同样是名词卡的内容：同一产出里两个专名可能被读成同一物、或需要区分（概念名与参数名、命令名错位是高发位）。加一行把关系写死："X 是 Y 的运行时对象"，或"X 与 Y 的区别在……"。读者带着"这俩是不是一个东西"的疑问离开任何一处，执行就会分叉。

专名有四类高发漏网形态，发出前逐一对照：

1. 缩写（文档名、模块名的简称）——首次出现必展开一次全称，无例外；
2. 项目内部行话与一字多义简称——按专名处理，首现给白话备注；
3. 字面义与实指义脱节的词（拿常见词表达圈内义）——换直白词，不靠备注硬撑；
4. 概括项目背景的数字提法（"N 小时预算"式）——看着像普通描述、实指一组既定事实，按专名给内容或出处。

最易漏的恰是作者天天用的词。

发出前自检三扫：

1. 扫名词覆盖——按上面四类过一遍，含裸编号（"编号须带内容"的执行遗漏在这里拦截）；扫的是全文一切位置：标题、状态行、标签行、表格、注释、头部元信息，不只正文段落——缩写和编号最爱藏在元数据行里；沿用旧稿的段落额外过一遍——旧词对作者最熟、对读者最陌生，是漏网最高发区；产出会落盘、或由新会话执行时，名词卡按"全新读者"标准收词；
2. 扫乱码、形近错字与读不通的病句——生僻怪字让人卡壳、让 AI 分词出错，半句话里换错一个词读者对着无解；
3. 扫自指声明——对自己产出的"无××""已××"类断言（"无自造流程词""已全部核对"），声明前实际核对一遍；这是缺失类断言的自指形态，同样最容易为假。

编号只有编号不算可解码，须带一句话内容。本产物的编号与历史决议或条款编号同名时，历史侧统一"日期 + 编号"并写、逐处都带——同一产出里不允许有的带日期有的裸编号。

判断所依赖的事实（先后顺序、默认值、数量、阈值）各带一句理由或出处。

收益两头：人免翻页（判断不被查证打断），AI 免猜测（猜错会顺着写进后续产出，是正确性风险）。

1. **禁链**：仓库长期文档（CLAUDE.md、docs/、spike/ 等）不写指向临时草稿目录（chat/draft/、chat/temp/、chat/consolidate/ 等）的指针；要引用其中结论，把结论连同依据（文档章节号、决议编号、日期）独立成文。
2. **跨文件引用** = "<文档名> - <标题原文>"（编号 + 标题文字，例：TechnicalSolution.md - 4.3 关键设计点）；文档改名、标题改名、编号更改后，全库 grep 旧名同步更正防死链。
3. **文件内引用** = "<标题原文>"（跨文件形态去掉文件名与分隔符，例：4.2 模块组成、第 13 章验收标准）；api.md 的 § 编号保留 § 前缀（例：§4 失败路径契约）；"第 N 章"式编号后直接接标题文字、不加空格；同名编号跨文档撞车时升级跨文件形态消歧；标题文字与句中既有词重叠时用「」包裹消歧。
4. **低于标题粒度**（粗体领句段、清单、表行）：地标词不冒充标题，用"标题原文 + 的「粗体领句词」段 / 的 (Q) 四级标题 小节"（例：TechnicalSolution.md - 9.2 SQLite 关系型数据 的「工程要求」段；仓库先例：api.md - §5 行为语义指针 的"TechnicalSolution.md - 7.2 核心阶段端点的 2026-09-25 段"）。节引用可取标题原文逐字前缀——截取不改字，标题内联反引号不进串。行号只作辅助锚（与规则 4 的定位锚条款同口径），主锚 = 文件路径 + 标题原文。
